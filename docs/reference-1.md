# reference.md

# 职业教育专业教学标准构建课程库领域模型参考规范

## 1. 专业标准库字段

`teaching_standard_library` 固定字段：

| 字段 | 说明 |
| --- | --- |
| `standard_id` | 标准唯一编号 |
| `major_code` | 专业代码 |
| `major_name` | 专业名称 |
| `education_level` | 培养层次 |
| `major_category_code` | 专业大类代码 |
| `major_category_name` | 专业大类名称 |
| `major_class_code` | 专业类代码 |
| `major_class_name` | 专业类名称 |
| `basic_study_years` | 基本修业年限 |
| `applied_industries` | 对应行业 |
|`occupation_types`|主要职业类别|
|`primary_postions`|主要岗位群|
|`certificate_types`|职业证书类别|
|`trainning_goal_summary`|培养目标摘要|
|`course_structures`|课程结构|
| `total_hours_rule` | 总学时规则 |
| `practice_ratio_rule` | 实践学时比例规则 |
| `original_from` | 来源文件 |
| `hash_digest` | SHA-256 |
| `status` | active/review/superseded |
| `notes` | 备注 |

无法从 PDF 或页面确认的信息留空，不得猜测。

### 1.1 数据提取规则

- 培养层次：一般由入学基本要求部分内容推断，如“中等职业学校毕业、普通高级中学毕业或具备同等学力”类似表述则为“高等职业专科”，如果类似“初级中等学校毕业或具备同等学力”则为“中等职业专科”；
- 专业大类名称/代码：由"职业面向"表“所属专业大类（代码）”获取；
- 专业类名称/代码：由"职业面向"表“所属专业类（代码）”获取；
- 对应行业：由"职业面向"表“对应行业（代码）”获取；
- 主要职业类别：由"职业面向"表“主要职业类别（代码）”获取；
- 主要岗位群：由"职业面向"表“主要岗位（群）或技术领域”获取；
- 执业证书类别：由"职业面向"表“职业类证书”获取；
- 培养目标摘要：由“培养目标”通过LLM摘要获得；
- 课程结构：由"课程设置及学时安排"的“课程设置”"专业课程"总结获取，一般包含专业基础课，专业核心课和专业拓展课三部分；

### 1.2 专业标准库状态规则

新构建的专业标准库记录统一进入 `review` 状态。课程库记录不单独维护
审核状态；业务专家以一个专业标准及其全部课程库记录为审核单元。

- `review`：标准库及其课程库记录已构建，尚未完成业务专家审核，不对
  课程库业务查询提供可用结果；
- `active`：业务专家确认该专业标准对应的课程库记录后，专业标准库状态
  推进为可用，关联课程库记录随之可检索、可用于课程体系生成；
- `superseded`：已有后续有效标准，保留历史来源和课程记录，但不作为
  默认可用标准。

课程库的事实、标签和建议课时均由所属专业标准的整体审核结论统一控制，
不得再为单门课程增加 `confidence_level`、`need_confirm` 或
`review_status` 字段。

## 2. 文档结构章节识别

专业教学标准通常包含：

```text
1 概述
2 专业名称（专业代码）
3 入学基本要求
4 基本修业年限
5 职业面向
6 培养目标
7 培养规格
8 课程设置及学时安排
8.1 课程设置
8.1.1 公共基础课程
8.1.2 专业课程
（1）专业基础课程
（2）专业核心课程
（3）专业拓展课程
8.1.3 实践性教学环节
8.1.4 相关要求
8.2 学时安排
```

实际标准可能略有格式差异，应使用标题语义和编号联合识别，不依赖固定页码。

## 3. 课程库内容说明

课程库的核心内容包含专业基础课、专业核心课和专业拓展课的课程知识体系与
学时设置。专业代码、专业名称和培养层次属于父级专业教学标准，不在课程记录
中重复存储。

### 3.1 专业基础课程

标准常见表述：

```text
主要包括：A、B、C、D 等领域的内容。
```

或中职：

```text
一般设置4门。包括：A、B、C、D等领域的课程。
```

数据提取规则：

1. 按中文顿号、逗号、分号拆分；
2. 删除“等领域的内容”“等领域的课程”；
3. 保留标准原课程名称；
4. 不自行改名；
5. `typical_work_task_description` 留空；
6. `teaching_content_requirement` 留空；
7. 标签按课程领域保守归纳；

### 3.2 专业核心课程

专业核心课程表常见列：

```text
序号
课程涉及的主要领域
典型工作任务描述
主要教学内容与要求
```

每个来源行映射到一门标准课程。首次出现的唯一键创建课程，后续命中同一
`library_id + course_type + standard_course_name` 的来源行追加证据，不再创建
第二条课程记录。

课程名称直接由“课程涉及的主要领域”列提取，不额外推断或寻找其他课程
名称来源；该列的原文即写入 `standard_course_name`。

必须保留：

- 课程名称；
- 典型工作任务描述全文；
- 工作内容；
- 工具原文；
- 主要教学内容与要求全文；
- 来源页码。

跨页续表处理：

1. 以序号和课程名称为主键；
2. 页末未结束内容与下一页同序号续表合并；
3. 不重复保存续表标题；
4. 合并后进行页面图像核验。

### 3.3 专业拓展课程

数据提取规则与专业基础课程相同。

专业拓展课程是候选池，不代表学校全部开设。

### 3.4 来源行保真与幂等

课程库必须设置以下唯一性约束：

```text
UNIQUE (library_id, course_type, standard_course_name)
```

它表达的是同一专业教学标准、同一课程类型下只有一门同名逻辑课程，不是用于
判断或清理“噪声”。多个来源位置命中同一唯一键时，生成一条课程记录，并将
各来源顺序、章节、页码、表格行和 `block_id` 全部绑定到该课程，不能静默丢弃
后出现的证据。不同课程类型下的同名课程仍是不同记录。

重复治理产生的数据重复由 `normalized_ref_id` 和整批幂等替换解决。跨页续表
中同序号、同课程名称且具有连续证据的内容属于一个逻辑来源行，应在解析阶段
合并；重复表头属于表格结构，不生成课程记录。

### 3.5 课程准入边界

课程是否进入课程库只由文档结构决定：仅抽取专业基础课程、专业核心课程和
专业拓展课程范围内明确列出的项目。公共基础课程和实践性教学环节位于抽取
范围之外，因此不进入课程库。

不得使用“实训”“实习”“毕业设计”“项目”等名称关键词建立排除黑名单。
只要某个项目被标准明确列入上述三类专业课程，就应按原文保留，不得因名称
看似非课程而过滤。

## 4. 课程库固定字段

课程库固定 18 个课程自身字段，不得随意增加已取消字段、父标准公共字段或
逐课程审核字段。

| 英文字段 | 中文说明 |
| --- | --- |
| `course_id` | 课程唯一编号 |
| `standard_course_name` | 标准课程名称 |
| `course_type` | 专业基础课程/专业核心课程/专业拓展课程 |
| `suggested_total_hours` | 建议总学时 |
| `suggested_practice_hours` | 建议实践学时，包含在总学时中 |
| `suggested_hours_range` | 建议学时区间 |
| `hours_setting_basis` | 建议课时设置依据 |
| `typical_work_task_description` | 典型工作任务及工作内容原文 |
| `teaching_content_requirement` | 主要教学内容与要求原文 |
| `knowledge_tags` | 知识标签 |
| `skill_tags` | 技能标签 |
| `tool_tags` | 工具标签 |
| `literacy_tags` | 职业素养标签 |
| `match_keywords` | 自动生成的匹配关键词 |
| `match_text` | 自动生成的语义检索文本 |
| `source_standard` | 来源标准名称 |
| `source_section` | 来源章节 |
| `source_page` | 来源页码 |

禁止重新增加：

```text
alias_names
job_group
work_content
ability_goal
ability_tags
technology_tags
related_certificate
```

证书、岗位群和专业职业面向可保存在专业标准库，不进入本课程库主表。

`major_code`、`major_name`、`education_level` 只存储在
`teaching_standard_library`。课程记录通过 `library_id` 关联父标准；后续
业务视图如需展示专业上下文，应通过关联读取，不得复制到
`teaching_standard_course`。

### 4.1. 课程 ID 规则

```text
<前缀><父标准专业代码或稳定标准标识>-<课程类型码><两位序号>
```

课程类型码：

| 课程类型 | 代码 |
| --- | --- |
| 专业基础课程 | B |
| 专业核心课程 | C |
| 专业拓展课程 | E |

示例：

```text
VC530701-B01
VC530701-C01
VC530701-E01
```

序号按专业教学标准中出现顺序生成。

课程顺序调整时，应尽量保留既有 ID；增量更新优先通过父标准、类型和课程
名称映射旧 ID。父标准专业代码为空时，使用父标准的稳定内部标识生成课程
ID，但不得把该标识写回或伪装成专业代码。

---

### 4.2. 标签提取规则

#### 4.2.1 知识标签 `knowledge_tags`

回答：

```text
学生需要掌握什么知识、规则、原理、模型和方法？
```

提取动词：

```text
掌握、理解、熟悉、了解
```

标签示例：

```text
平台规则、用户画像、SEO、数据分析指标体系、供应商管理、交互设计
```

主要由培养规格，专业核心课程主要教学内容与要求表的“主要教学内容与要求”中提取，不得保留完整句子，不保留“掌握”“了解”等动词。

#### 4.2.2 技能标签 `skill_tags`

回答：

```text
学生能够完成什么工作动作或技术任务？
```

提取动词：

```text
制定、分析、采集、处理、设计、制作、实施、优化、管理、调试、评估
```

标签示例：

```text
商品选品、运营目标制定、数据可视化、广告投放、原型设计、机器人调试
```

主要由培养规格，专业核心课程主要教学内容与要求表的“主要教学内容与要求”中提取，专业核心课程应尽量覆盖原文全部关键动作。

#### 4.2.3 工具标签 `tool_tags`

只记录真实工具：

```text
软件、系统、平台、设备、仪器、数据工具、管理工具
```

示例：

```text
ERP系统、CRM系统、数据分析工具、图形图像处理软件、3D扫描仪
```

无稳定工具要求时填写：

```text
无特定工具要求
```

主要由专业核心课程主要教学内容与要求表的“典型工作任务描述”中提取，不得为了非空强行填写“计算机”“办公软件”，除非标准明确或课程确有稳定使用场景。

#### 4.2.4 职业素养标签 `literacy_tags`

根据专业培养规格、课程性质和任务场景归纳。

常见标签：

```text
数据意识、用户意识、服务意识、合规意识、风险意识、质量意识、
成本意识、创新意识、团队协作、国际视野、审美意识、版权意识
```

职业素养标签应体现课程差异，禁止所有课程机械填写相同标签。

#### 4.2.5 标签为空规则

| 字段 | 空值处理 |
| --- | --- |
| `knowledge_tags` | 原则上不允许为空 |
| `skill_tags` | 原则上不允许为空 |
| `tool_tags` | 无工具时填“无特定工具要求” |
| `literacy_tags` | 原则上不允许为空 |

基础课和拓展课标签属于系统归纳，但不在课程记录中保存逐条确认标记。它们
与同一专业标准下的其他课程字段一起，纳入专业标准库的整体 `review` 审核；
业务专家确认后，由专业标准库状态统一推进为 `active`。

### 4.3 推导批处理规则

培养目标摘要、课程标签、建议课时、`match_keywords` 和 `match_text` 是
推导字段。系统必须按“一个专业标准及其全部待推导课程”组织批处理，避免
为每门课程单独调用 LLM。

1. 每个专业标准最多发起一次 LLM 批量推导请求，输入该标准已通过事实提取
   和规则校验的课程集合、培养目标、培养规格、学时规则及其来源定位；
2. 该次请求同时返回培养目标摘要，以及严格按输入 `course_id` 对应的全部
   课程标签和课程复杂度判定；输出中的 `course_id` 必须与输入及
   `teaching_standard_course.course_id` 完全一致，不得修改、重新生成，也
   不得按数组顺序、课程名称或稳定课程序号回填；
3. 可由确定性规则完成的拆分、标签有序去重、课时边界校验、`match_keywords` 和
   `match_text` 生成，必须在本地完成，不调用 LLM；
4. 仅在规则无法完成的培养目标摘要、标签归纳和课程复杂度判定上调用 LLM；
5. 输入内容、`ai_prompt_profile` 配置引用、输出和重跑必须按专业标准整体
   留痕；模型别名、Profile 版本和提示词版本通过该配置引用追溯，不在课程库
   推导记录中重复保存。推导必须选择 AI 治理中对应任务场景的已激活
   `ai_prompt_profile`，并使用其中的提示词、输出 Schema、温度、token 上限
   和脱敏策略。该 Profile 的默认 `litellm_model_alias` 为空；非空 Profile
   模型别名优先，否则回退到环境变量 `DEFAULT_GOVERNANCE_MODEL` 对应的 AI
   治理模型。课程模块不得硬编码其他模型别名。
   业务专家审核通过前不得将推导结果作为可用课程库数据。
6. 采用集合完全匹配校验输入和输出的 `course_id`：未知、缺失、重复或被修改
   的 `course_id` 均使整批推导失败，禁止部分课程落库，以避免推导字段与课程
   主数据错位。

## 5. 匹配字段生成

### 5.1 `match_keywords`

生成顺序：

```text
standard_course_name
+ 典型工作任务名称
+ knowledge_tags
+ skill_tags
+ 有效 tool_tags
+ literacy_tags
```

规则说明：

1. 拆分标签；
2. 去空；
3. 去重；
4. 保持首次出现顺序；
5. 以中文顿号连接；
6. “无特定工具要求”不进入结果；
7. 不加入专业代码、来源页码和建议课时。

伪代码：

```python
keywords = ordered_unique(
    [course_name]
    + task_names
    + knowledge_tags
    + skill_tags
    + valid_tool_tags
    + literacy_tags
)
match_keywords = "、".join(keywords)
```

### 5.2 `match_text`

固定模板：

```text
课程名称：{standard_course_name}。
适用专业：{major_name}（{major_code}）。
学历层次：{education_level}。
课程类型：{course_type}。
典型工作任务及工作内容：{typical_work_task_description}。
主要教学内容与要求：{teaching_content_requirement}。
知识标签：{knowledge_tags}。
技能标签：{skill_tags}。
工具标签：{tool_tags}。
职业素养标签：{literacy_tags}。
```

规则：

- 空字段整段跳过；
- “无特定工具要求”整段跳过；
- 不加入建议课时，避免影响课程语义匹配；
- 源字段更新后重新生成；
- 不由教研人员人工改写。
- 模板中的 `major_name`、`major_code`、`education_level` 必须在生成时从
  父级 `teaching_standard_library` 读取，不在课程记录中冗余保存。

## 6. 建议课时生成

### 6.1 总原则

专业教学标准通常只规定人才培养方案总学时和比例，不逐门规定课程学时。

课程库中的课时必须标注为：

```text
建议课时
```

不得写成：

```text
标准规定课时
教育部要求本课程学时
```

建议课时用途：

```text
课程库默认值
→ 自动生成课程体系
→ 学校调整
→ 人才培养方案总量校验
```

### 6.2 学时基本单位

建议总学时优先使用：

```text
16、24、32、48、64、80、96、112
```

核心课程和职业本科课程优先采用 16 学时的整数倍。

建议实践学时通常使用 8 学时的整数倍，且：

```text
suggested_practice_hours <= suggested_total_hours
```

### 6.3 课程复杂度权重

#### 专业基础课程

| 类型 | 建议总学时 |
| --- | --- |
| 理论认知型 | 24—48 |
| 理论+案例型 | 32—64 |
| 工具/数据/设计基础型 | 48—96 |

#### 专业核心课程

| 类型 | 建议总学时 |
| --- | --- |
| 单一执行任务 | 48—64 |
| 多任务综合执行 | 64—80 |
| 完整业务流程/综合项目 | 80—96 |
| 复杂管理、设计、数据建模或研发 | 96—112 |

#### 专业拓展课程

| 类型 | 建议总学时 |
| --- | --- |
| 素养/认知拓展 | 16—32 |
| 标准应用拓展 | 32—48 |
| 技术/工具/项目拓展 | 48—64 |
| 职业本科高级技术拓展 | 64—96 |

### 6.4 实践比例

| 课程性质 | 建议实践比例 |
| --- | --- |
| 理论基础课 | 20%—40% |
| 案例/方法基础课 | 40%—55% |
| 工具/数据/设计基础课 | 55%—70% |
| 专业核心执行课 | 55%—70% |
| 综合项目/设计/研发核心课 | 65%—75% |
| 实践型拓展课 | 60%—75% |

### 6.5 培养层次校验

#### 中等职业教育专科

优先读取标准第 8.2 节。常见规则：

```text
三年总学时不少于3000
公共基础课程一般约占1/3
专业课程一般约占2/3
实践性教学原则上不少于50%
选修课程不少于10%
实习累计不超过6个月
```

中职课程强调基础操作、岗位执行和规范训练，不宜将单门课程课时设置得过高。

#### 高等职业教育专科

常见规则：

```text
总学时不少于2500
公共基础课一般不少于25%
实践性教学原则上不少于50%
选修课程不少于10%
实习累计一般为6个月
```

高职专科课程强调完整工作任务、综合实践和岗位应用。

#### 高等职业教育本科

常见规则：

```text
总学时不少于3200
公共基础课一般不少于25%
实践性教学原则上不少于60%
选修课程不少于10%
实习累计一般不少于6个月
```

职业本科课程应体现：

- 复杂业务问题分析；
- 技术方案与管理方案制定；
- 数据建模与技术应用；
- 产品、服务与流程设计；
- 技术研发、改进和成果转化；
- 综合项目实施和评价。

### 6.6 汇总校验

基础课+核心课建议总学时只是专业课程主体，不应直接填满人才培养方案。

必须给以下内容预留空间：

```text
公共基础课程
专业拓展课程选修
综合实训
岗位实习
毕业设计
创新创业和特色课程
```

若基础课+核心课建议总学时过高，应降低单门建议值，而不是挤压实习和选修空间。

## 7. 专业标准整体审核规则

课程库不设置逐课程置信度、确认或审核字段。每次构建完成后，所属
`teaching_standard_library.status` 必须为 `review`。业务专家审核的对象是：

- 专业标准事实字段及其来源；
- 该专业标准的专业基础、专业核心和专业拓展课程集合；
- 核心课程的任务原文、教学要求原文和跨页合并结果；
- 课程标签、建议课时、匹配字段及其批量推导依据；
- 来源行恢复、课程章节边界和字段缺失异常。

业务专家确认课程库记录符合标准后，统一将专业标准库状态推进为 `active`；
发现新版标准时，将旧标准及其关联课程库按版本关系置为 `superseded`。

## 8. 质量检查清单

### 8.1 来源质量

- [ ] 专业基础课程列表全部提取；
- [ ] 专业核心课程表全部提取；
- [ ] 专业拓展课程列表全部提取；
- [ ] 核心课程跨页续表已合并；
- [ ] 核心课程数量与表格序号一致；
- [ ] 同一父标准、同一类型、同一名称仅有一条课程记录；
- [ ] 合并到同一课程的全部来源位置和证据均已保留；
- [ ] 仅专业基础、专业核心和专业拓展课程章节进入课程库；
- [ ] 专业课程章节内的项目未被名称关键词黑名单误删。

### 8.2 字段完整性

- [ ] 所有记录有课程 ID；
- [ ] 所有记录有标准课程名称；
- [ ] 所有课程均关联专业教学标准，专业名称、代码和层次由父标准统一提供；
- [ ] 所有记录有课程类型；
- [ ] 核心课程任务原文和教学要求非空；
- [ ] 知识、技能、素养标签非空；
- [ ] 无工具课程填写“无特定工具要求”；
- [ ] 来源章节和页码可追溯。
- [ ] 所属专业标准库状态为 `review`，待业务专家完成整体审核。

### 8.3 匹配字段

- [ ] `match_keywords` 非空；
- [ ] 无重复关键词；
- [ ] 不含“无特定工具要求”；
- [ ] `match_text` 非空；
- [ ] 空字段未写成“无明确标签”；
- [ ] 建议课时未写入语义文本。

### 8.4 课时质量

- [ ] 建议总学时合理；
- [ ] 建议实践学时不大于总学时；
- [ ] 课时区间包含建议总学时；
- [ ] 建议课时不冒充标准规定；
- [ ] 汇总后为公共课、选修、实习和毕业设计保留空间；

### 8.5 整体审核与状态推进

- [ ] 标签、建议课时和匹配字段按一个专业标准的课程集合批量推导，未对
  单门课程重复调用 LLM；
- [ ] 规则可生成的字段未调用 LLM；
- [ ] 业务专家已对该专业标准及其全部课程库记录完成整体审核；
- [ ] 仅审核通过后，专业标准库状态由 `review` 推进为 `active`；
- [ ] 被新标准替代时，旧标准状态变更为 `superseded`，历史课程记录保持
  可追溯但不作为默认可用数据。
