# 职业能力分析 SKILL：NEXUS OpenAPI 与数据支撑分析

日期：2026-10-26。代码基线：`8aff0c4`。本地 API：`http://127.0.0.1:8000`。

实施更新（2026-10-26）：下文保留的是 `8aff0c4` 实施前快照，提到“当前 active 限制”“待补地区/职业面向”等均为当时观察。本轮已实现岗位 `region`、教学标准 `occupation`、公开读取去 active、131 份标准职业面向专项补录和 SKILL/生成器适配；实测公开标准 131 份、课程 3,300 条。最终范围与验证见 [实施审查证据](review/wk_occupational_competency_openapi_skill_review_evidence.md) 和 [脱敏验收结果](testing/artifacts/occupational_competency_openapi_skill_acceptance_20261026.json)。

## 1. 结论与分析边界

**现有 NEXUS 公开工具已具备生成岗位 PGSD 初稿所需的主体资料读取能力。当前需要优先调整的是专业教学标准的 `active` 读取限制，以及 SKILL 对平台来源、检索记录和引用的适配；无需先补建 PGSD 数据库，也无需增加发布机构、发布日期、版本的核验流程。**

本分析采用用户最新确认的约束，覆盖此前 SKILL 的同类要求：

1. 所有资料检索统一使用 `docs/generated/public-function-tools` 中的 NEXUS 工具。不要求 SKILL 原文中的同名检索函数存在。
2. 职业证书通过 NEXUS 联网搜索取得；职业分类大典、专业教学标准、岗位资料及其他依赖资料均从 NEXUS 资产平台取得。
3. NEXUS 平台内容默认具有权威性，不额外核验发布机构、发布日期、修订版本或官方来源链接，不把这些元数据缺失计为数据缺口。
4. 专业教学标准读取不以 `active` 为前提。当前代码仍存在的 `active` 筛选属于待调整的接口行为。
5. SKILL 用于生成新的 PGSD 成果，不依赖已有 PGSD 分析数据。旧分析、能力项和能力图谱均不进入必要依赖链。
6. 对照 SKILL/reference 的输出契约，PGSD 与 KSA 双视图由 Agent 基于同一组事实生成；无需平台预存 KSA 分类或双模式文本。
7. 平台权威性可以默认信任，但仍需实际读取采用的内容，判断其是否与目标岗位有关；不能把“平台中存在一份文件”直接当作已读到支持某条要求的正文。

本轮仅分析与读取验证，没有修改上述公开接口、SKILL 或业务数据库。标准取消 `active` 限制等内容均为待实施建议。公开读取会正常记录访问审计；直接数据库检查采用只读事务。

## 2. 检查材料与实测范围

- 完整对照 [SKILL.md](e2e/occupational-competency-analysis/SKILL.md)、[reference.md](e2e/occupational-competency-analysis/reference.md) 和 [JSON 校验及 HTML 生成器](e2e/occupational-competency-analysis/scripts/render_competency_analysis.mjs)。
- 检查 [公开工具说明](generated/public-function-tools/README.md)、55 个生成工具的参数与 HTTP 绑定，以及实际路由、查询条件、序列化和响应结构。
- 使用用户提供的 API Caller 对本机服务执行 **22 次公开读取请求，全部返回 HTTP 200**，涉及资源发现、大典、标准列表/详情、标准课程、岗位列表/详情、文档列表、章节读取、实体候选、证据解析和已有图谱查询。
- 只读检查开发库的数量、来源覆盖及必要字段可读性。没有执行联网搜索、付费模型调用、生成岗位结论或回写正式 PGSD。
- [脱敏验证记录](testing/artifacts/occupational_competency_skill_api_audit_20261026.json) 保留接口状态、trace ID、数量和正文续读结果，不保存 API Key。

接口返回 200 只表示该请求执行成功。已有图谱接口的一次实际返回为 `available=false, reason=not_generated`；不能把 200 当成图谱已存在。生成本技能成果也不要求先有该图谱。

## 5. 优先需要调整的内容

### 5.1 取消教学标准读取的 active 限制：确证的接口行为差异

代码中 [standard_statement](../nexus-api/nexus_api/api/open_business.py) 当前明确要求 `TeachingStandardLibrary.status == "active"`，课程查询又复用了这个条件。这与用户最新要求不一致。

建议调整范围：

- 标准列表、标准详情。
- 标准课程列表、课程详情。
- 资源发现中标准及课程的数量。
- 专业实体候选中来自标准库的候选范围。
- 如继续保留原文关联图谱读取，取消其中针对 teaching_standard 的额外 active 限制；图谱仍只读已生成结果。
- 公开工具描述、API 文档和相关测试同步更新，移除“仅 active 可消费”的描述。

取消的是标准业务状态限制。文档 `available`、当前有效 normalized ref、分类匹配、投影与文档版本对应等现有可读性条件继续按平台契约处理；不自动激活标准，不触发 AI 治理，不为扩大数量改写文档状态。

**临时可用路径：**先经 `find_documents(resource_type="teaching_standard")` 发现文档，再读取章节或 normalized content。已有 131 份标准原文可以走这一路径，生成初稿不必等待结构化投影调整。

### 5.2 将 SKILL 的资料入口改为 NEXUS：执行契约适配

这不是要求新增一套检索接口，而是更新 SKILL/reference 对“从哪里取资料”和“怎样记录检索”的约定：

| researchChecks 类别 | 实际入口 | 记录含义 |
| --- | --- | --- |
| dictionary | NEXUS 职业分类大典查询 | 记录实际名称/分类检索条件和读到的定义、任务。 |
| teaching_standard | NEXUS 标准查询或标准文档查询、章节读取 | 记录实际专业、层次、标题检索条件及采用内容。 |
| certificate | NEXUS `search_web_search` | 记录真实联网搜索词、日期、采用的证书资料及适用范围。 |

原有三个类别可以保留；无需为了平台检索伪造联网搜索记录。`queries` 可记录实际检索文本及关键过滤条件；可选增加 `retrievalMethod`/工具名用于说明，但不是完成输出必需的新 API。

对平台来源，`verified` 应解释为“已从可信平台读取到所采用的内容”，不再要求额外验证发布权威性。`not_found` 表示本次在平台已入库范围内未找到，不能写成全国没有该职业/标准。`unavailable` 对应实际访问失败；不能以计划执行的参数冒充已执行检索。

### 5.3 平台引用与当前生成器校验不一致：确证的适配缺口

[生成器 validate](e2e/occupational-competency-analysis/scripts/render_competency_analysis.mjs) 当前要求所有 source 均有非空 `publisher`，且除 `kind=user` 外必须有 HTTP(S) URL。NEXUS 大典查询不返回这些字段；标准文档也不必具有外部 URL。

这属于**输出引用契约需要支持平台材料**，不是平台缺少权威元数据。不能为了通过校验编造原始发文机构、外部 URL，或把所有平台资料一律伪装为用户材料。

建议用最小适配解决：

- source 增加平台来源标记及引用对象，例如 `provider=nexus`、`resourceType`、`recordId`，文档可带 `normalizedRefId`、`sectionId`。
- 对平台来源允许 `publisher`、`publishedAt`、外部 `url` 留空，页面显示“NEXUS 数据资产平台”及资料标题/摘录/定位；不将平台名称冒称为原始发布机构。
- 保留本成果内稳定 source ID，通过 `sourceRefs` 引用；数据库 ID 放在平台定位字段，不强迫作为成果的全局稳定 ID。
- `verifiedAt` 记录实际读取日期，`excerpt` 来自实际采用内容。平台权威默认成立与“正文是否已读取”分别表达。
- 离线 HTML 中保留摘录及平台定位，不内嵌 API Key，不把临时下载签名 URL 当永久引用，也不暴露本机文件路径。

大典查询当前已返回完整的定义和任务，Agent 可以直接构造引用，不必等待新增证据接口。若要统一取证体验，可在 `get_evidence_bundle` 增加 `occupation_dictionary` 引用类型，并支持按记录 ID 定位；这属于便利性增强，不是读取大典内容的硬阻塞。

### 5.4 职业证书搜索：已有主体能力，正文覆盖需要条件性补强

当前 NEXUS 联网搜索已经采用 DeepSeek，服务端请求 `need_content=true`，返回标题、URL、正文内容及上游元信息。不存在“需要先接入另一种搜索引擎”这一缺口。

执行时须落实两点：

1. **只读取证，`auto_ingest=false`。** 生成工具的 HTTP binding 已给出该执行器默认值，但服务端请求默认仍为 true。执行器必须真正注入 false，不能因为省略参数而排队进入文档入库流程。此处是对既有绑定的执行要求，不要求新建 PGSD 保存接口。
2. **不要把默认 OneYear 当成证书文件的有效范围。** 有效标准可能早于一年。现有接口已允许显式起止日期，执行器可使用宽日期区间检索，不必先改 API；日期范围不代表证书有效期。

仍有一个条件性能力缺口：当前公开工具没有按指定外部 URL 只读获取完整网页、附件/PDF 并继续读取的通用能力。DeepSeek 返回内容没有统一的完整性/续读契约；只读 Firecrawl 搜索主要返回线索，自动抓取入库分支不符合本技能只读取证的需求。

如果搜索结果正文已经覆盖证书性质、发证/评价组织、等级及所采用考核内容，现有接口即可完成该次分析；如果只有摘要或关键内容位于附件，则目前只能继续经 NEXUS 搜索补充片段，或明确标记未取得所需内容。若要求这类场景也稳定完成，再补充 NEXUS 的指定 URL/附件只读读取能力及内容截断标识，不要求引入 SKILL 中任何同名工具。

本轮没有执行真实证书搜索，因此这一部分是代码/契约判断，不是上游服务的成功率或正文完整率实测结论。

## 6. 数据覆盖和检索便利性：按需增强

这些内容不应扩大为生成初稿前必须完成的平台建设。

### 6.1 岗位到职业、专业的候选关联

当前 `resolve_business_entities` 支持 major、course、enterprise、industrial_park，主要做名称/代码精确与子串匹配；不提供岗位别名到大典职业，再到相关专业的专门关联查询。

Agent 仍可使用大典定义/任务、专业简介、标准职业面向和岗位正文进行判断，并在初稿说明映射边界。因此无需把关联表作为硬前置。

若要减少检索轮数，优先增强已有查询：大典增加职业代码/记录 ID 筛选；标准支持职业名称或职业面向检索；实体候选支持 occupation/job-role 类型并返回关联依据。关联结果保持候选，不把相似名称自动认定为同义岗位。全量翻页和正文读取是现有可用的回退方式。

### 6.2 地区及岗位层级过滤

市场岗位接口已支持岗位名、行业、经验、企业、学历、采集时间等过滤，返回地址；目前没有地区专门过滤、统一岗位层级或职业代码过滤。

未限定地区时不会阻塞。指定省市时，可对已取得岗位地址做本地筛选，但可能需要较多翻页。若地区限定成为常用需求，建议增加地区过滤并说明精确度；职级/资历仍可结合已有经验过滤与职责内容判断，不必先新增岗位画像主表。

聚合接口返回记录数，按 `raw_jobs.id` 计数，不是按来源 URL 或企业独立性去重的技能统计。单次分析可在读取样本后按 URL、企业及职责内容复核重复；SKILL 不强制输出市场比例，无需为生成 PGSD 先开发技能频率聚合 API。

### 6.3 职业标准、技能标准与资料覆盖

职业分类大典已有 1,329 条，但这是已入库范围，不是任意岗位都存在同名条目的保证。找不到同名职业时可查上位/相关职业并说明边界。

教学标准已有多层次正文；部分内容可能重复上传，需按资料内容和本次任务选择，不必增加发布版本核验流程。

职业/技能标准可通过现有文档工具读取，不要求另建专用表。本轮按当前可读资料标题检查，发现一份明确题为“无人机驾驶员国家职业技能标准”的文档；这只是标题检查，不能推断其他正文中不存在相关内容，也不能声称已覆盖所有职业。遇到目标岗位平台资料不足时，应记录“平台已入库范围内未找到”，后续按业务岗位补充资料，不从互联网绕过非证书资料来源边界。

没有具体目标岗位前，不能仅凭全库数量判定其任务、工作内容和评价要求是否充足。适合按业务实际选取的岗位做一次完整取数与生成验收，再决定补哪些原始资料。

## 7. 输出字段如何由现有资料支撑

| 输出内容 | 必要输入 | 由谁完成 | 是否需要新 API/预存 PGSD |
| --- | --- | --- | --- |
| occupation、industry、region、level、范围假设 | 用户输入、大典、岗位与行业资料 | Agent 确定范围并说明假设 | 不需要。 |
| relatedRoles 的 alias/collaborator/progression、boundary | 目标及相关岗位正文、职业定义 | Agent 比较责任和交付边界 | 不需要；关系无法确证时用 inferred/pending。 |
| 1–3 条核心 tasks，含描述和产出 | 大典工作任务、标准相关原文、真实岗位过程 | Agent 按完整职业行动归并 | 不需要旧任务库；不套用一个专业的全岗位群。 |
| workContents 的 title/action/output/qualityCriteria | 职责、工作步骤、标准与企业要求 | Agent 拆解并写出可观察结果 | 不要求平台预存四个同名字段；超出原文的评价表达注明归纳。 |
| requirements 的 PGSD/KSA 双分类与双表述 | 前述来源及证书相关要求 | Agent 基于同一事实分类、表达 | 不依赖已有 PGSD/KSA 数据；不能固定换算分类。 |
| workContentIds | 本次生成的工作内容及每项要求适用范围 | Agent 显式关联并由生成器校验 | P 只关联一个；G/S/D 关联真实应用环节，不需要迁移旧能力项。 |
| sourceRefs、supported/inferred/pending、reason | 实际读到的原文和分析过程 | Agent 区分来源支持、归纳和未明确内容 | 已有正文读取可支撑；平台引用契约需按 5.3 适配。 |
| researchChecks | 三类实际查询及读取结果 | Agent 记录真实执行信息 | 适配入口和语义，不增加形式化“标准认证”服务。 |
| JSON、双模式 HTML、XLSX/CSV/PDF | 通过校验的本次成果 JSON | 现有本地生成器与浏览器导出 | 不缺平台导出、保存分析、创建项目或治理 API。 |

“平台可信”并不意味着 Agent 新写的每一项质量标准、协作边界和能力表达都成为平台原始事实。来源直接支持的可标 supported；从职责分解出的表达可标 inferred 并给出 reason；材料未覆盖的特定要求可 pending。无需为此调用 AI 治理或回写资产。

## 8. 建议的最小执行链

1. 接收岗位及范围；调用 `discover_data_resources` 了解已入库覆盖。
2. 从 NEXUS 大典查询目标名称/相关名称，读取定义和工作任务，明确正式职业与实际岗位边界。
3. 经专业候选、专业简介或标准文档定位相关专业和层次；标准查询若受当前 active 限制，走标准文档读取回退。
4. 读取标准中相关的职业面向、培养规格、知识技能段落，按 `next_offset` 续读；不把标题或课程名当成采用正文。
5. 读取匹配岗位及必要行业材料，按本次范围挑选、去重，不将全库记录数写为该岗位样本数。
6. 通过 NEXUS DeepSeek 搜索证书，强制关闭自动入库，并使用合适日期区间。结果内容不足时继续搜索或记录未完成项。
7. 将实际采用的资料登记为平台/联网来源与三类检索记录。平台无需重新证明权威性，未知的元数据不补造。
8. Agent 生成本次任务、工作内容和能力，完成 PGSD/KSA、内容关联、证据状态及一致性检查。
9. 运行 SKILL 生成器，验证离线 HTML 与表格/PDF 导出。成果保持独立初稿，不调用正式 PGSD 写入、资产管道或 AI 治理。

## 9. 实施优先级与验收

| 优先级 | 建议动作 | 性质 | 可核验的验收结果 |
| --- | --- | --- | --- |
| P0 | 标准与课程公开读取取消 active 限制，联动发现数量和候选范围 | 公开接口行为调整 | review 标准关联可读文档时可查询；数量与实际列表一致；不自动激活或修改资产状态。 |
| P0 | SKILL/reference 统一采用 NEXUS 工具和平台可信前提 | 执行契约适配 | 非证书资料只来自平台；不再执行权威元数据核验；检索记录对应真实查询。 |
| P0 | 生成器/页面允许平台来源缺少外部 URL、原始 publisher，保留平台引用与摘录 | 输出引用适配 | 无官方 URL 的平台大典/标准可正确引用和导出；不伪造 URL、机构或将平台材料全部改成 user。 |
| P0 | 证书搜索执行器落实 auto_ingest=false 和合适时间范围 | 已有绑定的执行约束 | 搜索不产生文档入库任务，不因默认一年窗口漏掉早期仍适用资料。 |
| P1，按稳定性要求 | NEXUS 增加指定外部 URL/附件的只读正文读取，或搜索结果完善覆盖/截断信息 | 条件性新接口能力 | 当证书关键内容只在附件中时也能读取；无正文覆盖时清楚返回限制，不触发资产入库。 |
| P1，按使用频率 | 岗位地区过滤、大典代码/ID 筛选、标准职业面向查询及实体候选增强 | 检索效率增强 | 按地区或职业查询减少全量翻页；不自动认定同名/相似岗位为同义关系。 |
| 按岗位覆盖 | 补充目标岗位实际缺少的标准、岗位或行业资料 | 数据补录 | 以目标岗位读取结果为依据补资料，不以全库数量或字段形式要求泛化建设。 |

首轮验收可以选择一个平台已有资料的岗位，检查“平台取数 → 证书联网取证 → 新 PGSD 文件 → 离线展示与导出”的完整链条。未限定具体岗位前，本报告不宣称已有数据能够覆盖全部行业和岗位。

## 10. 明确不需要补建的能力

- 不把既有 PGSD、旧职业能力图谱、旧任务库作为本技能输入前提，也不因其为空或缺少 KSA 映射而阻塞生成。
- 不增加发布机构、发布日期、标准版本或外部来源权威性认证流程。
- 不以缺少 SKILL 原文中的同名工具函数为由新增接口；所有检索能力都归 NEXUS 公开工具。
- 不增加证书资产库作为联网搜索前置；当前平台里即使已有证书文档，也不替代本次规定的证书联网检索。
- 不新增正式分析保存、PGSD 项目创建、成果入库或 AI 治理接口。
- 不将 HTML、Excel、CSV、PDF 本地生成误列为平台 OpenAPI 缺失；现有导出需在实际生成成果时验证。本轮没有生成岗位成果，也未执行其导出测试。
