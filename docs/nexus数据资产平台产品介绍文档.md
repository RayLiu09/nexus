# NEXUS 数据资产平台产品介绍

**版本**：V1.0  
**适用对象**：职业院校、教育集团、产教融合平台及需要统一治理数据与知识资产的组织  
**产品形态**：企业级数据与知识资产管理平台

## 一、研发背景

职业教育组织持续积累教材、课程标准、人才培养方案、实训指导书、评价标准、企业项目、岗位需求和政策报告等数据。这些数据来源多样、格式复杂，分散在网盘、业务系统、个人电脑和外部采集渠道中，存在检索困难、版本混乱、人工整理成本高和复用效率低等问题。

传统文件管理只能解决“保存”，不能回答数据是否可信、谁可以使用、是否适合进入 AI 应用以及结论如何追溯。NEXUS 因此被建设为连接原始数据与业务智能应用的数据治理中枢，将数据接入、校验、资产化、解析、标准化、AI 治理、规则决策、知识加工和检索服务纳入同一条可审计链路。

一期 P0 聚焦 D1-D4 试点域，优先打通从数据接入到语义检索的可运行闭环；知识图谱、问答语料、评测标准库和产品化运营中心作为后续扩展能力，不改变一期的资产和治理基础。

## 二、产品定位

NEXUS 是面向职业教育和企业知识管理场景的**数据与知识资产治理平台**。平台不是网盘、单纯全文搜索引擎，也不是独立 AI 网关。它使用既有 LiteLLM 进行模型路由和供应商适配，由 NEXUS 管理治理 Prompt、输出 Schema、质量评分、规则护栏和正式治理结果。

平台服务四类角色：平台/数据管理员负责数据源、规则、Prompt、权限和审计；业务专家负责治理复核和质量校准；运维人员负责作业追踪与故障处理；API 调用方通过授权接口消费资产和检索结果。适用场景包括教学资料治理、人才培养方案管理、产教融合数据管理、政策与行业研究以及带来源引用的智能检索和问答。

## 三、产品模块

本章严格按照 `nexus-console` 当前侧边栏导航编写。控制台导航分为“总览、数据工程、资产与治理、访问与审计、个人工作”五组，以下名称与实际导航标签一致。

### 3.1 总览

#### 工作台

工作台提供接入、作业、治理和基础运行状态的全局概览，并提供待处理事项入口。用户可以从概览进入原始数据台账、作业中心、资产目录和治理追踪。

### 3.2 数据工程

#### 数据源

数据源页面注册和维护多源接入方式，当前覆盖本地文件上传、NAS 同步、Crawler 爬虫、数据库对接和 API 推送等来源类型，并维护数据源基本信息和默认治理提示。

#### 原始数据台账

原始数据台账查看接入后保留的原始对象、批次信息和校验摘要，提供原始数据追溯与回放入口。该模块只负责原始留存和追踪。

#### 作业中心

作业中心展示接入后自动创建的处理作业、阶段进度、失败原因和关联对象，并提供重试、重处理、重治理等操作入口，覆盖文档和记录处理作业。

### 3.3 资产与治理

#### 资产目录

资产目录展示数据资产、当前版本读模型、版本历史、标准化引用和索引状态。资产详情可查看概览、版本、AI 治理、质量、知识切片、血缘和审计信息。

#### 治理审核

治理审核面向需要人工处理的 `review_required` 标准化资产。业务专家提交最终治理结论，包括分类、分级、结构化标签、质量处置、组织范围和复核原因，并保留 AI 建议、证据和审计记录。

#### 治理追踪

治理追踪查看 AI 治理运行、治理建议、质量评分、规则命中、决策过程和治理结果，跟踪资产从 AI 建议到正式结论的变化。

#### 规则配置

规则配置提供分类、分级、标签、质量评分和知识类型等治理规则的结构化编辑。当前控制台采用保存后对后续治理运行生效的方式，变更保留操作者和审计信息。

#### 治理 Prompt

治理 Prompt 页面维护治理流水线各阶段使用的 Prompt 模板。编辑模板会形成新版本并归档旧版本，模板支持治理任务所需的规则和文档占位内容。

#### AI Prompt

AI Prompt 页面维护 AI 治理和质量评分使用的 Prompt 配置，包括 Prompt 版本、LiteLLM 模型别名引用和输出 Schema 版本。该模块不提供 AI 网关、模型供应商、密钥或路由管理。

### 3.4 访问与审计

#### 权限与审计

权限与审计页面维护本地用户、角色、组织范围、API Key，以及审批和审计日志。平台在资产访问、检索和 API 返回前执行权限过滤，并记录登录、访问、治理变更和权限拒绝等行为。

#### API Caller

API Caller 页面管理面向上层系统的 API 调用方、访问凭据和权限范围，支持对调用主体进行识别、授权和停用。

#### 智能检索

智能检索是面向业务用户的检索和问答入口。用户在权限范围内查询已治理知识资产，查看回答、检索结果和来源引用。

#### 检索联调

检索联调面向平台管理员和业务专家，用于验证检索参数、召回结果、权限过滤和引用信息，辅助定位检索质量问题，不改变正式资产治理结果。

### 3.5 个人工作

#### 我的工作区

我的工作区汇总当前用户相关的待办、复核任务、近期处理记录和个人关注内容，帮助用户从个人视角继续处理平台任务。

## 四、产品功能

### 4.1 数据接入与资产化

平台支持单文件、批量、目录、NAS、Webhook、业务记录推送和爬虫采集。接入后保留原始对象和批次，执行 `ingest_validate` 校验；随后分别进入文档 Pipeline 或记录 Pipeline。资产化负责创建资产和版本锚点，标准化负责生成 `normalized_document` 或 `normalized_record`，两者职责明确分离。

### 4.2 多格式解析与标准化

平台根据 MIME 类型自动选择 MinerU 模型；图片、PDF 和 TIFF 自动启用 OCR，解析图片与结果文件一并保存。标准化引用 `normalized_asset_ref` 包含 `source_type`、`content_type`、`title`、`language`、`governance`、`quality` 和 `lineage` 字段。治理输入只能是标准化文档或标准化记录，不直接使用原始文件、原始 JSON 或 MinerU 原始输出。

### 4.3 AI 治理和质量评分

AI 对标准化资产提出业务域、分类、分级、标签和组织范围建议，并从完整性、准确性、时效性、一致性等维度评分。建议携带模型别名、Prompt 版本、Schema 校验、证据引用和置信度。AI 建议必须经过字段白名单、脱敏、规则护栏和状态机判断，才能影响正式治理结果。

### 4.4 规则决策与人工复核

规则检查必填字段、格式、质量阈值、敏感级别和组织范围。版本状态包括 `processing`、`available`、`review_required`、`archived`、`disabled`、`failed`。只有拥有有效标准化引用、治理质量通过、必填治理信息完整、无阻断规则且满足唯一可用版本约束时，版本才可进入 `available`。低置信度、规则冲突、高敏感度或质量不合格的资产进入人工复核。

### 4.5 知识切片与语义检索

通过治理的资产被拆分为带标题路径、文本和页码或块定位的 `knowledge_chunk`，P0 默认使用 PostgreSQL pgvector。检索先执行身份、组织、分级和治理状态过滤，再进行语义召回与重排；结果返回资产、版本、标准化引用、知识切片和来源定位。

### 4.6 版本、血缘、权限和 API

资产版本、解析工件、标准化引用、治理运行、规则版本、索引投影和原始对象均可沿血缘链路追溯。平台使用本地用户、角色、组织范围和 API Caller 控制访问，并通过统一 `/v1` 业务 API 为上层系统提供资产查询、作业查询、检索、问答和审计能力。重试、重处理、重治理和 AI 重评分均支持幂等和审计。

## 五、产品特点

### 5.1 AI 辅助而不越权

AI 处理重复性识别和评分，专家保留正式决策权；所有采纳、修订和人工覆盖均可审计。

### 5.2 一源多用

同一份教材、培养方案或企业资料完成一次治理后，可服务资产目录、结构化查询、语义检索和上层业务应用，减少重复清洗。

### 5.3 证据和血缘完整

知识切片关联标准化引用，结论可以回到章节、页码、表格和原始对象，满足质量追责和知识产权管理要求。

### 5.4 权限与安全前置

数据默认按 L1/L2 管理，L3/L4 仅在明确例外和授权条件下处理；权限过滤在检索和 API 返回前执行。

### 5.5 技术架构可演进

LiteLLM、MinerU 和 pgvector 均处于清晰的适配边界内，后续可替换模型或检索后端而不改变资产和治理语义。

### 5.6 面向业务闭环

平台把数据接入、作业处理、治理复核、资产管理、检索服务和审计放在同一条可追踪链路中，为职业教育数字化和产教融合提供可信数据底座。

## 结语

NEXUS 以数据资产为核心、以知识治理为抓手、以可信检索为出口，将组织分散的数据沉淀为可管理、可验证、可复用的长期资产，让 AI 进入业务流程的同时保留规则、专家、权限和审计对最终结果的控制权。
