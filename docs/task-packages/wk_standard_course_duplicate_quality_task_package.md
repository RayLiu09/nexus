# Task Package: 标准课程格式重复质量治理

日期：2026-11-16。单 Agent 顺序实施。

## 来源与目标

- 来源：公开 Agent OpenAPI 场景报告 D05；同一标准的核心课程存在仅空白差异的名称，例如“互联网产品 设计”和“互联网产品设计”。
- 目标：在标准课程投影时识别这类格式重复，保留源课程行、来源序号、证据绑定以及已有派生/人工修正字段，并通过目录质量标记提示人工核验。

## 冻结契约

- 逻辑检查键为 `course_type` + Unicode NFKC 规范化后移除空白的课程名。
- `course_name_whitespace_duplicate_count` 表示同一检查键下多出的源课程行数量。
- 诊断不自动合并持久化行，也不覆盖源名称、派生字段或人工修正；后续合并必须依据标准身份、来源序号和证据人工确认。
- `quality_flags` 在标准课程目录中可见，课程列表和详情仍返回原始课程行及证据。

## 不在范围内

- 不建立全局课程主数据，不做语义别名合并。
- 不改变现有 `UNIQUE(library_id, course_type, standard_course_name)` 合同，不删除历史课程行。
- 不处理 P2 SQL/索引性能和全量检索性能验收。

## 验收

- 空白/Unicode 格式差异会产生质量标记，完全相同的源课程仍按既有逻辑合并。
- 源课程名称、source_order、evidence_bindings、派生字段和人工修正不丢失。
- 标准课程库回归测试、编译检查和 `git diff --check` 通过。
