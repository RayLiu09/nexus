# Agent OpenAPI 实际场景验收任务包

- 日期：2026-10-22；单 Agent 执行。
- 来源：`agent_openapi_gap_analysis_2026-10-22.md` 第 6 节、ARCHITECT.md 的公开业务 API 边界、SPEC.md 的资产可见性和证据要求、WORKFLOWS.md 的验收证据要求。
- 目标：使用用户提供的 API Key，通过真实 HTTP 执行六个 Agent 场景，交付完整报告与可复现、脱敏的请求及断言记录。
- 范围：公开 `/open/v1` API、只读数据核验、无凭据测试脚本、测试报告；必要时临时启动 API，关闭 Worker、采集调度和数据同步，结束后停止本任务启动的服务。
- 排除：C 类接口、外部搜索自动入库、创建测试业务数据、重建图谱、修改资产/治理/权限/API Key、Console 启动、提交推送。
- 禁止：改变架构、模型、正式业务状态或可见性以使测试通过；泄露 Key 或原始敏感数据；把单元测试结果当作实际场景通过。
- 交付：HTTP 场景脚本、脱敏请求证据、六场景结果矩阵、问题和数据缺口、认证/边界检查、复现方法。
- 验收：实际调用有状态码、trace_id、耗时和关键锚点；严格区分通过、失败和数据阻塞；确认业务数据无测试写入；报告可独立阅读。接口问题若需修复另行记录并运行相应回归。
- 执行中用户调整：政策场景的区域参数改为“重庆市”或“成都市”；以重庆市完成主链路，同时记录成都市严格日期筛选的数据缺口。园区场景补充重庆本地样本；园区 API 使用其已支持的 q 查询地域文字，不注入未声明的 region 参数。
