# Task Package: 职业分类大典基础数据与列表

日期：2026-10-26。状态：实现、测试与开发库导入完成；用户已授权提交和推送。

## 来源与目标

- 用户要求将 `docs/e2e/中华人民共和国职业分类大典（2022年版）职业名录.xlsx` 导入系统基础表，并在资产中心专业数据卡片增加职业分类大典列表。
- 遵循 ARCHITECT/SPEC 的本地鉴权、独立领域事实、nexus-api `/v1` 业务接口和现有资产中心列表约定；Next.js 页面服务端加载，客户端管理查询和分页。

## 冻结契约与范围

- 新建 `occupation_dictionary` 只读基础表；2022 版 + 职业编码唯一，不依赖资产版本、AI 治理、标签或知识管道。
- 源表列依次映射职业类别、职业大类（源列所属大类/中类）、职业小类、职业名称、职业定义、工作任务。保留编码、来源文件、源行号和 PDF 页码；按用户补充指令以同编码 PDF 正文修复缺失或损坏的字段，不使用 AI 或推测内容。
- 同编码重复优先正式中文职业名，遇多个冲突正式记录拒绝导入。源表 1410 行、1339 个编码；尝试使用提供的同版 PDF 补齐后，名称、定义或工作任务任一仍为空的记录丢弃，并输出清单。
- 版本化 JSON 种子随 Alembic `20261026_0122` 导入，独立命令支持 dry-run/幂等 apply；整批校验、事务导入、审计。
- 列表 API：`/v1/occupation-dictionary`（API caller），`/internal/v1/occupation-dictionary`（用户），分页参数沿用现有协议；`major_group`、`minor_group`、`occupation_name` 字面子串 AND 过滤，分类同时支持编码检索。
- 页面：`/asset-center/major/occupation-dictionary`；六列完整正文可换行阅读，三个输入条件、检索、重置、服务端分页；无编辑/删除入口。卡片数量来自同一基础表。
- 修改模型、迁移、导入工具、API、资产中心、相应测试与架构/产品/原型说明；不修改其他任务工作区改动，不引入 AI 或新治理分类。
