# Task Package: 岗位采集计划自由输入

日期：2026-11-05。状态：实现与验证完成，人工 Review Gate 在合并前完成。单 Agent。

## 来源与目标

按用户要求调整岗位采集创建表单；参考 ARCHITECT.md Ingest Layer、SPEC.md API
Push data sync、Prototype v2.2 数据采集及 WORKFLOWS.md 的 API/Frontend UX Gate。
现有 C6/Catalog 任务的“仅允许目录岗位”约束由本次用户要求替代。

## 范围与冻结契约

- 岗位使用现有 `query_config.keywords: string[]`，支持建议选项和自由输入，
  中英文逗号分隔，清除两端空白及重复/空条目；1–30 个，每项最多 120 字符。
- 专业类别使用可选 `query_config.professional_category` 文字字段（最多 128 字符）；
  空白规范为空并省略，既有计划仍可读取；不新增主表或迁移，不写入目录字典。
  目录分类仅影响建议选项，切换/清空不丢弃已输入岗位。
- 创建、编辑、复制共享校验与回显；后端允许未入目录的岗位。
- 仍限制每计划最多 5 区域、岗位×区域最多 100 组。上游只接收现有 keyword/region/pageLimit，
  专业类别保留在计划内，不作为上游请求字段。
- 允许修改 data-sync 前端、适配器、计划校验、聚焦测试、合同/产品/页面文档及验证记录。
- 禁止改动身份权限、现有审计/幂等/运行状态、调度器、采集结果处理、模型路由、密钥、
  其他治理审核改动；不新增服务、网关、反向指针或绕过治理。
- 本轮不提交、推送或创建真实上游采集任务。

## 交付与验收

- 前后端实现及文档，无迁移。
- 后端覆盖自定义岗位创建/编辑、分类空/自定义值及回显、30/31 边界、100 组合限制，
  审计/幂等沿用；模拟上游验证不发送专业类别。
- 前端与浏览器覆盖中英文逗号、自定义/清空分类、分类切换保留岗位、最多 30、
  超限阻止保存、编辑复制保留值、未入目录岗位正常提交。
- 定向测试、TypeScript、定向 lint 与差异检查，记录对应 Review Gate 自检与人工合并门禁。
