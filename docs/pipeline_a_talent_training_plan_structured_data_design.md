# 人才培养方案结构化数据设计

## 定位

`talent_training_plan.v1` 是 Pipeline A 从 `normalized_document` 投影出的院校级人才培养方案领域读模型。它面向结构化检索和后续图谱投影，不承担人才培养方案合规校验、学分核算或文本完整性判定。

输入边界固定为 `normalized_asset_ref` 指向的 `normalized_document`。解析原文件、原始 MinerU JSON、表格图片都不能直接写入领域表。规范化表格 block 可以保留单表 `table_html`、Markdown 文本及页码/坐标定位，作为可复核的表格证据；这不是保留或消费 MinerU 原始输出。

## 数据模型

主表 `talent_training_plan` 一行对应一个规范化文档投影，且以 `normalized_ref_id` 幂等替换。主要标量字段是：

- `institution_name`、`major_name`、`major_code`
- `education_level`、`study_duration`
- `training_goal`
- `training_specification` JSON
- `career_orientation` JSON
- `certificates` JSON

`training_specification` 记录有证据的能力、知识要求和素质要求。`career_orientation` 记录行业、职业、岗位以及岗位核心能力和学习领域。行业、职业、岗位、技能、证书都保持为该方案的带证据属性，不在本阶段创建平台全局主数据或反向关系表。

从表 `talent_training_plan_course` 是方案拥有的课程行，记录课程名称、课程目标、课程内容、证据及 `skill_refs`。它不是全局课程主数据：相同名称在不同院校、版本或方案中仍是不同的课程事实。

课程表的字段映射不能依赖单一字面列名。解析器先对规范化表头消除空白、换行和中英文标点差异，再按受控的语义别名解析课程名称、课程目标和课程内容，例如将“教学目标”“学习目标”“课程定位与学习目标”归一到 `course_objective`，将“主要教学内容”“学习内容”归一到 `course_content`。目标/内容/名称字段分别配置排除词；匹配冲突或没有足够语义锚点时保持空值，不以 LLM 或相邻列猜测补全。持久化课程事实仍保留实际源表头与 block/locator 证据。

岗位能力和学习领域的多值拆分只使用规范化表格中可追溯的结构边界：独立表格行/单元格、`<br>`、段落或列表边界，以及源文本明确提供的换行、分号、顿号。不得根据“能力”“技能”等字面后缀或空白切分连续文本。

当转换器识别到“职业岗位（群）+ 岗位核心能力”表中存在长文本、重复能力信号而没有任何源边界时，会将该表标记为 `structure_lost`。这是检测信号，不是事实切分规则。仅在该表仍有解析阶段保存的表格图片时，规范化阶段才通过 LiteLLM 调用 `DEFAULT_GOVERNANCE_MODEL` 作视觉转写恢复。模型被严格要求只返回 JSON 行项目；接收端要求 JSON-only、精确字段集合、完整且无重复的行号、与源岗位名归一化一致、数组类型的项目以及至少两个能力项，任何说明、代码围栏、未知字段、行不匹配或格式错误都会被拒绝。持久化到 `normalized_document.blocks[].table_structure_recovery` 的仅是已验证的项目和序号，不保存提示词或模型原始响应。

领域投影只读取该规范化恢复字段，不读取图片、MinerU 原始 JSON 或模型原文。恢复调用会把检测到的全部行号和岗位名作为必返约束传入；输出必须完整覆盖该集合，少一行即整表恢复失败，不接受部分恢复。恢复成功时生成独立技能/学习领域事实并记录块定位、列名和单元格项目序号；恢复失败或图片不可用时仍保留岗位事实，但不从被压平单元格生成一个错误的聚合技能节点。历史文档可通过受审计的规范化修复工具补写该字段后，再重建方案领域投影；该操作不新建资产版本、运行或通用 Evidence Graph。

## 图谱视图边界

人才培养方案不进入通用 Evidence Graph（`knowledge_graph_*`）加工队列。该通用图谱面向跨文档语义抽取、LLM 候选治理和 chunk evidence；人才培养方案需要的是基于已验证领域投影的确定性业务视图，两者不能混用。

课程知识图谱是每份方案的必备只读视图，直接由方案、课程、课程目标、课程内容、课程 `skill_refs` 生成。它不创建新的课程、知识点或技能主数据，也不额外持久化图谱副本。

岗位能力图谱是可选只读视图：只有规范化证据提供岗位及其核心能力时才生成。只有岗位名称、没有能力事实的方案返回 `available=false`，而不是构造推断关系或空图谱。

课程和岗位关系只在规范化证据显示以下链路时投影：

```text
人才培养方案 -> 岗位 -> 岗位核心能力
人才培养方案 -> 岗位 -> 学习领域 -> 课程 -> skill_refs
```

`skill_refs` 由课程名和同方案学习领域匹配产生，并携带原岗位能力表的 block/locator 证据。后续可把这些计划内节点映射到补充的产业、行业或职业主数据，但映射应是独立的可审计过程，不能把抽取时的文本值当成既有主数据 ID。

## 检索与接口

读接口支持机构、专业名称/代码、层次、修业年限以及岗位、技能、证书、课程过滤。主表 JSON 过滤提供 P0 的受控属性检索；课程字段使用方案拥有的关系表过滤。面向大规模 JSON 条件查询时，可在实际负载证明后增加 PostgreSQL GIN 索引，不改变现有领域边界。

`major_profile.v1` 保持为轻量专业介绍模型，不能因为名称或专业代码相同而替代 `talent_training_plan.v1`。前者描述专业概览，后者保留院校、版本和课程/岗位能力证据。
