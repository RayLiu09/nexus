# 职业能力分析执行参考

## 一、范围与检索

本技能面向一个岗位的职责和能力初稿。仅有岗位名时可开展工作：先确定名称含义，记录“未限定地区，按行业常见执行岗位分析”等范围假设；培养层次只有用户要求适配教学时才需要。范围无法唯一确定时提出关键澄清。

收到岗位名称即通过 NEXUS OpenAPI 工具集检索。除职业证书通过 NEXUS 联网搜索取得外，其余资料全部来自平台资产；不依赖已有 PGSD。平台内容默认权威，无需核验发布机构、发布日期、版本或官方链接。各类留下真实查询条件、实际日期、结果及适用范围；仍须读取实际采用的内容，不能仅凭目录名称推定正文。

### 三类必检资料

| 类别                           | 检索入口与思路                                                                                            | 核验及应用                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 职业分类大典 dictionary | NEXUS query_occupation_dictionary，按岗位名/别名查询，必要时查上位及相关职业 | 使用平台正式名称、职业代码、定义和任务；无需额外验证来源。没有同名条目时说明映射边界。适用职业/技能标准也从平台文档检索读取。 |
| 专业教学标准 teaching_standard | NEXUS query_teaching_standards，occupation 匹配对应行业、职业类别/代码或主要岗位，可叠加 major_code/major_name/education_level | 不要求 active；读取 career_orientation、培养规格及能力相关正文。只提取与岗位相关内容，不混用教学层次，不把课程名当任务。不验证发布机构、日期或版本。 |
| 职业证书 certificate | NEXUS search_web_search，auto_ingest=false，检索职业资格/技能等级/评价标准/考核内容 | 读取搜索结果正文，核对证书性质、发证/评价组织、等级、有效性及岗位适用性，不把培训证当国家职业资格。time_range 显式使用适合的宽日期区间，不默认只查近一年。 |

以上资料分别服务于职业定位、教学能力校准和等级/评价要求分析，结合真实工作过程使用。平台未收录匹配条目、未取得采用内容或证书不适用时如实记录，不拿无关材料凑数。正文内容或地区适用性冲突时保留冲突并标记待确认。

其余岗位检索围绕以下问题逐步收敛，不把搜到的数量当证据质量：

1. 在平台大典、岗位、专业简介和标准中查询目标及相关名称，识别职责边界。
2. query_market_jobs 使用 job_title、industry、region、experience 等实际参数。region 对原始工作地址做字面子串匹配，不用采集范围推断地点；列表/聚合均先过滤再分页。采集时间不等于招聘发布日期，资料少时说明限制，不虚构趋势或比例。
3. 用同样入口查询相关岗位，比较输入输出与协作边界；同来源 URL 的重复采集记录不当作独立佐证。

采用平台已有大典、标准、岗位及行业资料，证书另走 NEXUS 联网搜索。招聘页是该企业的样本，不能代表行业整体。尽量比较两个独立企业/资料来源；达不到时仍可交付有明确限制的初稿。

标准正文用 list_document_sections / read_document_section，按 next_offset 续读；也可使用 get_normalized_ref_content 或 get_evidence_bundle。HTTP 成功不等于读到所需内容。证书搜索未覆盖关键考核段落时，继续经 NEXUS 检索补充或记录限制，不用工具集之外的抓取函数，也不打开自动入库获取正文。

### 相关岗位关系

| 关系                   | 分析用途                                   | 示例                     |
| ---------------------- | ------------------------------------------ | ------------------------ |
| alias（同义/近同职责） | 合并岗位别名，注明行业差异                 | 首饰设计师 / 珠宝设计师  |
| collaborator（协作）   | 明确目标岗位交付接口，保留对方职责边界     | 首饰设计师与首饰制作工匠 |
| progression（发展）    | 说明更高层级或拓展方向，不写入当前必备能力 | 首饰设计师与设计主管     |

relatedRoles 中 `includedTaskIds` 表示页面分析覆盖其哪些任务，空数组表示只作范围说明；`boundary` 明确哪些职责不属于本次目标岗位。不要因为相邻岗位也被检索，就扩成一个专业全部岗位群。

## 二、从工作过程到能力

### 典型工作任务

参考原 occupation-analysis：以完整职业行动为单位，用“对象＋行动＋结果”或“业务情境＋工作过程”表达。标题建议 4–12 字，例如“首饰设计方案开发”；描述 1–2 句说明情境、责任、结果。不能写“首饰设计师”“设计软件”“设计基础课程”或一个孤立动作。

每个岗位原则上仅保留 1–3 条最核心的典型工作任务，不追求全面职责清单，不为凑三条拆分。选择直接形成岗位关键交付、体现核心专业判断、承担主要质量责任的完整职业行动；将同一交付过程中的执行步骤、沟通校核等支撑环节归到工作内容。一般性行政事务、低频外围职责及协作岗位责任不单列成典型任务。工作内容按核心任务真实过程展开，不设固定数量下限；任务多于三条时先按交付对象与责任归并并剔除非核心内容，不能仅删最后几条。相关岗位用于检索校准和边界说明，不自动增加目标岗位任务。

工作内容采用简短名词性标题，如“客户需求与设计约束”“设计图样与三维模型”；action 写执行动作，output 写交付物，qualityCriteria 写可观察的质量要求。任务之间按前后流程或并列职责排序，不把一段职责机械切成同粒度不一致的小标题。

### 两种模式共用同一要求

每条 requirement 有两种分类、两种表述，但只是一项核心要求。两种分类回答不同问题：知识/技能/素养描述要求的学习属性，PGSD 描述该要求在职业行动中的作用。禁止“知识=P、技能=G、素养=S/D”的固定换算。同一知识也可能是 G 或 S，专业技能通常是 P，问题解决也可能属于 D；按内容与应用范围判定。

| 分类           | 内容与表达                                                       | 示例                                                       |
| -------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| knowledge 知识 | “掌握/理解/熟悉＋概念、规则或原理＋适用边界”，写清具体知识       | 掌握贵金属与宝石的材料性能及设计适用限制。                 |
| skill 技能     | “能＋行动＋对象/工具＋结果或质量要求”                            | 能使用 CAD 构建结构完整、尺寸准确的首饰模型。              |
| quality 素养   | “在＋情境＋遵循/保持/主动＋可观察行为”，不写抽象人格标签         | 在设计迭代中主动核验来源并记录原创设计依据。               |
| P 职业能力     | 工作内容的专业行动，“能＋具体行动＋对象/工具＋结果”              | 能依据材料性能选择符合造型与制作要求的材料组合。           |
| G 通用能力     | 语言、数学、科技、人文、艺术、健康、信息技术等方法在任务中的应用 | 具备信息整理能力，能将客户需求转换为可核对的设计约束清单。 |
| S 社会能力     | 职业道德、法律、安全环保、沟通协作、项目管理、跨文化、公民责任   | 具备协作沟通能力，能与制作人员核对图纸和工艺接口。         |
| D 发展能力     | 学会学习、批判思维、问题解决、创新、创业                         | 具备持续学习能力，能试用新工具并评价其对设计质量的影响。   |

G/S/D 沿用项目现行维度；不要因为常见框架把沟通放 G，就静默改变本项目定义。所有要求的 workContentIds 必须非空，P 只挂一个工作内容；任务级 G/S/D 关联其真实应用环节。贯穿全过程时显式关联本任务全部适用工作内容，并写成有情境的要求；仅在评审或归档中应用的复盘能力应关联对应环节，不默认挂满全部行。KSA 模式直接在工作内容的知识、技能、素养列中显示；不设置“任务共享要求”区块。关联多项可在对应行复现，统计按唯一 requirement id 计数。处理旧数据的空关联时，先按内容复核补齐关联，不能自动归入任意一行或静默丢弃。

每个工作内容通常应有知识和技能要求；素养必须有真实情境，不为凑列重复写。每任务检查 G/S/D 的适用性，有不适用或未能确认的维度时写 task.notes，不强造要求。一条要求只写一个主要行动；合并同动作、对象、评价方式的重复项，把不同目标拆开。label 通常 4–12 字，基于意义提炼，绝不截取全文句首。

### 两种表述保持对应

knowledge 的 ksaContent 可描述原理；对应 pgContent 转为该原理服务的行动。转换不得加入新工具、证书、法定标准或更高责任范围。quality 转换为 S/D 时保留原行为情境。难以归类时先复核拆分，不用任意分类隐藏争议；存为初稿的待确认项需填写 reason。

## 三、证据与初稿状态

| evidenceStatus | 页面名称   | 要求                                                                                          |
| -------------- | ---------- | --------------------------------------------------------------------------------------------- |
| supported      | 来源支持   | 已核验的正文实质支持该要求，sourceRefs 非空；语言可概括，不能夸大原文                         |
| inferred       | 分析归纳   | 基于职责/用户材料拆解产生的训练、验收或分类表达；sourceRefs 可列底层依据，reason 说明推导边界 |
| pending        | 待专家确认 | 无足够证据、地域/标准适用性不明或来源冲突；reason 必填，不伪装成确证                          |

相关岗位、任务和能力均保留 evidenceStatus、sourceRefs、reason。引用多个来源不自动等于相互印证；同页转载视为一个来源。整个产物默认是“分析初稿”，不能自动升级成正式确认。

source.kind 可为 standard、official、industry、employer、user、other；来源含 title、scope、excerpt、limitations、verified（是否读到采用段落）和 verifiedAt（实际读取日期）。平台来源增加 provider="nexus"、resourceType、recordId，文档可加 normalizedRefId/sectionId；publisher、url、publishedAt 可缺省或留空，不填造原始机构或外部链接。平台来源保持原资料 kind，不一律改成 user。页面及导出必须保留平台名称、引用定位和摘录。

provider="web" 仅用于证书联网结果，需真实 HTTP(S) url；发布元数据已知时填写。缺省 provider 兼容旧文件。不得将 API Key、认证 URL、临时签名或本机绝对路径写入引用。verified 表示实际读到采用段落，不是二次权威认证；默认可信不意味着 Agent 新归纳的要求都是原文事实。

### 检索记录 researchChecks

顶层 researchChecks 必须恰好包含 dictionary、teaching_standard、certificate 三条记录。每条含 category、status、queries（真实检索词数组）、checkedAt（YYYY-MM-DD）、scope（地区、层次或等级适用范围）、summary（实际发现及限制）、sourceRefs（已登记来源 id）。

status 为 verified（已读采用内容，引用非空且全部已读）、not_found（实际检索未找到匹配资料）、unverified（只有线索，未读采用正文）或 unavailable（工具、网络或访问受限）。queries 写实际检索文本及关键过滤条件，例如 occupation=电商运营、education_level=高等职业教育专科；不伪造联网查询。retrievalMethod 可为 nexus_api 或 nexus_web_search，前两类使用前者，certificate 使用后者。unavailable 的 summary 写具体原因，无工具可用时 queries 可为空。not_found 仅表示平台已入库范围或本次证书搜索未找到，不代表资料不存在。找到教学标准不等于证明岗位必须持证。

## 五、页面与交付

浅色蓝白界面沿用项目视觉基调：顶部岗位标题和简要范围，相关岗位边界说明；左侧任务导航；右侧工作内容与能力对照表。KSA 直接在工作内容表格中展示三个维度，不另设任务共享区块；PGSD 展示工作内容级 P 与任务级 G/S/D，只显示有条目的任务层类别，避免空卡片。均保留产出、质量要求、来源和待确认状态。全文自然换行，不默认用省略号隐藏内容。“分析范围与资料说明”位于能力分析之后的页面底部，包含范围假设、资料限制及三类资料检索记录；打印时这些内容放在末尾资料部分。

支持全任务/单任务浏览、关键词搜索、仅看待确认、来源说明弹窗、下载 HTML、导出表格、下载 PDF。HTML 包含完整数据，重新打开仍可切换两种模式。Excel、CSV、PDF 导出当前模式和筛选范围，无匹配条目时明确提示调整筛选。Excel 必须是合法 OOXML XLSX，不得改 CSV/HTML 后缀冒充；包含“工作内容与能力”“能力明细”“分析范围与依据”三个工作表。CSV 保留任务、工作内容、编号、简称、全文、证据状态及来源，计数按唯一能力计算。JSON 作为独立成果，不在页面顶部提供入口。PDF 必须生成真实 PDF 文件，不能用 window.print 代替下载；assets/file-export.js 提供自包含的 XLSX 与分页 PDF 生成器，生成器将其内嵌到 HTML，无 CDN 或在线依赖。当前 PDF 为高清图像型，支持阅读打印但不可搜索复制文字，必须向用户说明。PDF 包含当前任务、能力、证据标识及末尾范围资料，长文本换行、跨页续表，不得截断。导出弹窗显示范围、生成结果与可再次下载的文件链接；提示“已生成并发起下载”，不保证宿主已经保存。表格同时提供 CSV 与复制到 Excel 备用，自动复制失败时显示并选中文本供用户手动复制。

在项目 sandbox 中部分下载可能被限制；不得访问父页面绕过限制，明确提示浏览器打开 HTML。来源 URL 只允许无凭据 http(s)；平台材料无 URL 时显示 NEXUS、资料名称、定位和摘录，不暴露本机绝对路径。

## 六、交付质量门

- 岗位范围、行业/地区/层级假设可见；相关岗位有职责边界与关系类别。
- 单岗位原则上不超过 3 条核心典型任务，聚焦主要交付和责任；典型任务是完整行动，工作内容粒度一致，均有产出和可观察的质量标准，不因未穷尽职责判为缺失。
- 每条要求有双分类、双表述、稳定 id、正确工作内容关联及来源/理由；P 不跨工作内容重复挂载。
- 已核验正文确实支持采用内容；归纳或证据空缺被标识，来源日期和统计不虚构。
- 三类必检资料都有真实检索记录、状态和适用范围；核验或访问失败可见，不编造职业代码、证书等级及准入要求。
- 两种模式切换、任务导航和搜索不改数据；每条能力关联具体工作内容，KSA 无任务共享区块，PGSD 无空类别卡片，计数不因重复展示增长。
- 分析范围、资料限制及检索记录置于底部。
- 页面离线加载，无网络请求或脚本错误；用户材料中的 HTML/脚本文本被安全显示。
- 实际验证导出的 JSON/XLSX/CSV/HTML/PDF，核验中文、格式、引用和 HTML 二次打开；检查两种分类与筛选的导出范围一致，PDF 页数、跨页长文与中文渲染正常。
- 不把初稿自动写回正式职业分析；交付明确哪些功能实测、哪些岗位结论待专家复核。
