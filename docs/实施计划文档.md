# 实施计划文档

主题：Chunk Quality 与 Policy/Report Section Context 优化  
日期：2026-08-02  
详细计划：`docs/chunk_quality_and_section_model_implementation_plan.md`  
质量报告：`docs/chunk_quality_report.md`

## 目标

本轮优化不以引入外部 `by title` / `by similarity` 切块策略为目标。
这些策略只作为质量参照。NEXUS 的实际目标是提升政策/报告、教材书籍
等场景下的检索、召回、上下文补全和引用可信度。

## 本轮边界

- 先做只读质量分析，不写数据库。
- 不新增迁移。
- 不改变现有 API 响应契约。
- 不从 raw 文件、raw JSON 或 MinerU raw output 构建治理/知识输入。
- 质量报告先输出到 `docs/chunk_quality_report.md`。

## 实施顺序

1. 建立只读 Chunk Quality Report。
2. 对已完成数据资产执行 chunk 质量分析。
3. 为政策/行业报告设计 derived section model 原型。
4. 将 policy/report section context 接入 query-time retrieval。
5. 增加 oversized chunk hard-max guard。
6. 建立检索评测集，按业务问题集验证优化效果。

## 关键交付

- `docs/chunk_quality_and_section_model_implementation_plan.md`：完整实施计划。
- `docs/chunk_quality_report.md`：首版 Chunk Quality Report。
- `scripts/chunk_quality_report.py`：只读 Chunk Quality Report 生成脚本。

## 当前执行状态

本轮已创建实施计划与 Chunk Quality Report，并已对当前 `.env.dev`
指向的已完成数据资产执行 live read-only 数据分析。报告遵守“不写数据库”
的边界，未新增迁移，未改 API，也未写入任何业务表、作业表或索引清单。

重新生成实测报告：
