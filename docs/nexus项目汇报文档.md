# NEXUS 企业数据与知识资产平台项目汇报

> 汇报部门：数据智能部
> 汇报日期：2026-08-26
> 文档定位：面向管理层与业务方的项目综合汇报，覆盖建设背景、核心技术实现设计、应用场景。

## 一、建设背景

### 1.1 项目定位

NEXUS 是一个面向职业教育领域的**企业数据与知识资产管理平台**。它不是文件管理系统，也不是搜索引擎，而是连接**"原始数据"** 与**"业务智能应用"** 之间的**治理与加工中枢**。

平台要解决的核心命题：

> 组织内大量散落在各系统、各部门的教学资料、培养方案、评价标准、企业案例、政策文件、岗位数据等，如何从"存着但找不到、找到但不敢用"，变为"可信赖、可检索、可追溯、可复用"的知识资产。

### 1.2 我们面临的核心挑战：沉睡的数据资产

**① 数据孤岛现象严重**
数据分散在 PDF、Office 文档、表格、数据库等不同载体中，彼此孤立、无法互通，形成看得见却用不了的"数据烟囱"。

**② 难以响应复杂业务查询**
业务问题跨领域、复合型强，传统关键词匹配只能返回碎片化信息，无法理解真实意图、无法进行深度关联分析，难以支撑高质量决策。

**③ 数据质量缺乏统一治理**
缺乏标准化的清洗、校验与更新机制，导致信息重复、错误或失效，直接影响分析准确性与决策可信度。

**核心影响：** 企业宝贵的知识资产长期"沉睡"，无法转化为生产力，成为数字化转型的关键瓶颈。

### 1.3 核心目标：构建统一、智能、可追溯的知识底座

将 **9 大类异构数据资产** 建成一个**支持统一语义检索、跨资产复杂问答、答案可追溯到原文**的知识底座，彻底打破数据孤岛。

| 序号 | 数据资产       | 覆盖内容                       |
| ---- | -------------- | ------------------------------ |
| 01   | 产业政策文件   | 宏观导向、扶持政策与行业规范   |
| 02   | 产业分析报告   | 市场规模、发展趋势与竞争格局   |
| 03   | 人才培养方案   | 培养目标、课程体系、就业方向   |
| 04   | 岗位需求数据   | 企业招聘画像与人才市场供需     |
| 05   | 职业能力分析表 | 岗位胜任力模型与核心技能要求   |
| 06   | 专业布点数据   | 区域分布、招生规模与开设院校   |
| 07   | 专业资源简介   | 院校专业特色、优势与培养亮点   |
| 08   | 专业教学标准   | 课程体系、教学大纲与质量标准   |
| 09   | 核心教材资源   | 精品教材、数字化课程与教辅资料 |

### 1.4 建设驱动力

- **业务驱动**：从分散式数据管理迈向智能辅助决策，支撑产教融合、专业建设、教学评价、人才画像。
- **技术驱动**：AI 大模型能力成熟，具备对非结构化数据进行语义理解与治理的可行性。
- **合规驱动**：教育行业对数据安全、知识产权、审计合规提出更高要求，敏感数据严格不出域、每次决策可追溯。

## 二、核心技术实现设计

### 2.1 端到端处理流程：从原始数据到智能检索

NEXUS 构建了**全链路自动化的知识处理闭环**：

```
① 数据接入 → ② 解析标准化 → ③ AI 智能治理 → ④ 知识深加工 → ⑤ 智能检索
```

| 阶段          | 关键动作                                                   |
| ------------- | ---------------------------------------------------------- |
| ① 数据接入    | PDF、Office 文档及各类数据库的统一接入                     |
| ② 解析标准化  | 智能解析提取文本、表格与图片，完成非结构化数据的结构化转换 |
| ③ AI 智能治理 | 自动分类、标签抽取与质量打分，构建规范化元数据体系         |
| ④ 知识深加工  | 基于语义的智能切块与向量化索引，自动生成知识大纲           |
| ⑤ 智能检索    | 意图理解、多策略并行分派、可信证据链汇总                   |

**核心架构优势：双轨并行** — 针对**非结构化文档**与**结构化数据**设计独立并行处理管线，在治理环节实现标准化汇合，确保异构数据以统一的知识标准进入加工环节。

### 2.2 五阶段数据治理体系

每个阶段都配备明确的质量关卡：

| 阶段                 | 关键动作                                   | 质量关卡                                   |
| -------------------- | ------------------------------------------ | ------------------------------------------ |
| ① 数据接入           | 统一接口、格式识别、来源登记、基础校验     | 不合规文件被标记退回                       |
| ② 资产化与标准化     | 解析、版面识别、表格提取、图片分离         | 每份资产有唯一身份、版本、来源谱系         |
| ③ AI 智能治理        | 分类分级、质量评分、知识类型识别、标签生成 | 高置信度自动生效，低置信度进入人工复核     |
| ④ 规则护栏与状态判定 | 业务专家定义质量、合规、业务规则           | 状态：可用 / 待复核 / 失败；决策全程可追溯 |
| ⑤ 知识加工与服务     | 拆解为可服务业务的知识单元                 | 独立开关 + 量化指标，全链路可观测回退      |

**关键约束：** AI 所有建议必须经过规则护栏验证，**AI 永远不能直接修改资产的正式状态**；每步决策均记录**决策追踪（Decision Trail）**。

### 2.3 知识加工：10 道工序的语义切块流水线

我们坚信"**加工质量决定检索的天花板**"，为此设计 10 道精细化工序，确保每一个语义切块（Chunk）都具备高可用性与高关联性：

| 工序                  | 目标                                           |
| --------------------- | ---------------------------------------------- |
| 01 政策章节标题识别   | 恢复文档丢失的章节层级，还原政策条款完整上下文 |
| 02 指标卡片提取       | 精准提取报告中的关键 KPI 数据，独立封装        |
| 03 导航块智能剔除     | 过滤目录、页眉页脚等冗余，保障信噪比           |
| 04 无意义内容深度清洗 | 移除水印、二维码描述等 8 类噪声                |
| 05 图表信息归属归并   | 图表标题、图例与本体智能关联                   |
| 06 跨页段落智能缝合   | 拼接因分页截断的长段落，还原完整语义           |
| 07 缝合后残留噪声清洗 | 二次清洗页眉残留、版权声明等次生噪声           |
| 08 结构化行记录表分解 | 岗位表、清单等按行拆分为独立记录               |
| 09 全链路章节路径注入 | 打上完整层级标签，支持"命中一点，返回全章"     |
| 10 冗余内容智能去重   | 通过语义指纹识别并合并重复内容                 |

### 2.4 差异化加工策略：基于资产类型建立业务领域模型

摒弃"一刀切"，我们为每一类资产**建立专属的业务领域模型（Domain Model）**，让数据结构与业务语义高度对齐：

**① 政策 · 报告文档模型**（产业政策文件 / 产业分析报告）
保留章节层级的语义切块，条款级溯源 → 按章节深度检索，完整还原上下文逻辑。

**② 结构化记录模型**（岗位需求数据 / 专业布点数据）
逐行拆解为独立记录，字段化建模 → 支持按岗位、地域、招聘人数等维度精准筛选。

**③ 专业画像模型**（专业资源简介 / 人才培养方案）
建模为 `major_profile` / `talent_training_plan`，按培养目标、课程体系、就业方向等 6 大核心板块拆解 → 快速定位专业核心特征与培养重点。

**④ 教学标准课程模型**（专业教学标准）
以"标准课程"为最小语义单元，针对每门课程抽取如下结构化领域字段：

| 字段                            | 说明                   |
| ------------------------------- | ---------------------- |
| `standard_course_name`          | 课程名称               |
| `major_name` / `major_code`     | 适用专业与专业代码     |
| `education_level`               | 学历层次               |
| `course_type`                   | 课程类型               |
| `typical_work_task_description` | 典型工作任务及工作内容 |
| `teaching_content_requirement`  | 主要教学内容与要求     |
| `knowledge_tags`                | 知识标签               |
| `skill_tags`                    | 技能标签               |
| `tool_tags`                     | 工具标签               |
| `literacy_tags`                 | 职业素养标签           |

→ 支撑岗位基线核对、能力要求校准、课程参照对齐、证书标准对照。

**⑤ 教材知识模型**（核心教材资源）
教材以"知识大纲 + 语义切块 + 章节图谱"三层联合建模，抽取知识点、能力点、章节层级 → 支持知识点级检索、关联与溯源。

**⑥ 能力图谱模型**（职业能力分析表）
提取能力节点、层级关系与关联路径，构建可视化图谱 → 支撑课程设置与人才评价。

**核心理念：** 领域模型让每类资产以"业务最自然的方式"被存储与使用，而非被压平成通用文本；后续所有检索、问答、图谱应用都基于领域模型直接生成，业务语义无损。

### 2.5 切块质量的量化追踪：7 大评估维度

拒绝"感觉切得好"，坚持"数据说了算"，将隐性质量问题转化为显性数字指标：

| 维度           | 评估内容                               |
| -------------- | -------------------------------------- |
| 结构覆盖完整性 | 章节路径是否完整，杜绝关键层级缺失     |
| 单元大小合理性 | 篇幅分布，规避过长碎片化或过短信息不全 |
| 边界风险控制   | 识别跨页面、跨标题的错误合并           |
| 无关噪声净化   | 检测目录、版权页、页眉页脚干扰占比     |
| 表格智能解析   | 验证大型表格的自动识别与结构化分解     |
| 大纲关联匹配   | 核对教材内容与标准知识大纲的映射关系   |
| 检索可用性判定 | 综合评估语义清晰度与索引完备性         |

### 2.6 检索架构：从"关键词匹配"到"意图驱动"（v2.0）

三层智能路由架构：

**① 意图理解与标签化** — 识别用户查询意图（信息 / 结构 / 知识），抽取"地区、行业、维度"等关键标签，路由守卫过滤无效请求。

**② 多策略并行分派** — 基于意图并行调用多工具（最多 4 个）协同工作，同步调取岗位需求、能力图谱、专业布点等多维数据。

**③ 可信证据链汇总** — 多源结果按逻辑智能聚合，每个结论标注精确引用来源，构建可追溯的证据链。

**五大核心检索场景：** 讯息查询 / 结构化查询 / 专业综合查询 / 教材知识查询 / 智能兜底机制

## 三、应用场景

### 3.1 五大核心检索业务场景

| 场景         | 面向问题                                       | 使用者               |
| ------------ | ---------------------------------------------- | -------------------- |
| 讯息查询     | 政策新规、行业动态、市场趋势的快速获取与解读   | 决策层、专业带头人   |
| 结构化查询   | 区域分布、专业统计、数据排行等复杂数据分析     | 教务、招生、规划部门 |
| 专业综合查询 | 培养目标、课程体系、就业前景等专业建设深度问答 | 专业负责人、教研室   |
| 教材知识查询 | 教材理论概念、实操步骤、案例解析检索           | 教师、学生           |
| 智能兜底     | 意图检索无结果时自动回退到全库向量搜索         | 全场景兜底           |

### 3.2 跨资产复杂问答示例

> **问题：** "面向直播电商产业，广东省有哪些院校开设了相关专业？对应的岗位能力要求是什么？"

NEXUS 的处理路径：

1. **意图识别** → 结构化查询（专业布点） + 能力图谱查询
2. **标签抽取** → 行业="直播电商"、地区="广东省"
3. **语义桥接** → 打通"直播电商产业"↔"电商直播"↔"直播运营"的表述差异
4. **多源并行调用** → 专业布点数据 + 岗位需求数据 + 职业能力分析表
5. **证据链汇总** → 结构化答案 + 每个结论标注引用来源，可追溯到原文

### 3.3 面向 AI Agent 应用：一键生成《专业人才需求调研分析报告》

NEXUS 治理后的多类知识资产，可直接被上层 AI Agent 通过**开放 API（`/open/v1`）** 调用，将过去人工需要**数周**才能产出的调研报告，压缩到**数小时**内自动完成，且每个结论均有角标溯源。

**报告目标**：贯彻职业教育教学关键要素改革要求，联通"产业—行业—职业—专业"链条，实现人才培养供给侧与产业需求侧的结构与质量匹配。

**NEXUS 9 类资产 → 6 章报告的映射：**

| 报告章节                 | 调用的 NEXUS 资产                                        |
| ------------------------ | -------------------------------------------------------- |
| 二、产业发展与环境分析   | 产业政策文件 + 产业分析报告                              |
| 三、行业人才需求分析     | 岗位需求数据 + 职业能力分析表 + 专业教学标准（岗位基线） |
| 四、专业人才培养现状分析 | 专业布点数据 + 人才培养方案 + 专业资源简介               |
| 五、人才供需匹配分析     | 岗位需求数据 + 人才培养方案 + 职业能力分析表（联合比对） |
| 六、专业人才培养优化建议 | 核心教材资源 + 专业教学标准 + 职业能力分析表             |

**AI Agent 与 NEXUS Open API 的关系与使用方式：**

NEXUS 对上层 AI Agent 定位为**"知识底座 + 开放服务"**：Agent 不直接访问底层数据库或模型，而是通过统一的 `/open/v1` HTTP 接口调用治理后的资产。所有调用凭 API Caller 密钥认证，可见性由 NEXUS 侧权限过滤，返回结果自带 `trace_id` 与来源引用，天然满足角标溯源要求。

_调用模式_：

```
AI Agent  ──HTTPS + X-API-Key──▶  NEXUS /open/v1  ──▶  治理后资产 / 领域模型 / 语义索引
              ▲                                              │
              └──────── ApiEnvelope（data + meta.trace_id + 来源）
```

_Agent 报告生成时的典型接口调用：_

| 报告需求                   | 调用的 Open API                                                         | 用途                                           |
| -------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------- |
| 产业政策与报告章节写作     | `POST /open/v1/query`（意图=讯息查询）                                  | Query Router v2 聚合检索 + 章节级证据 + 角标源 |
| 岗位群、招聘样本、薪资数据 | `GET /open/v1/record-assets/job-demand-records`                         | 结构化岗位领域事实查询                         |
| 职业能力与任务图谱         | `GET /open/v1/record-assets/ability-analyses/{id}/tasks`                | 能力节点、层级、任务树                         |
| 院校专业布点、招生规模     | `GET /open/v1/major-offerings/aggregate`                                | 按省级区域聚合布点                             |
| 课程开设覆盖率与频次       | `GET /open/v1/major-courses/aggregate`                                  | 课程体系匹配分析                               |
| 人才培养方案对标           | `GET /open/v1/talent-training-plans`                                    | 按院校、专业、岗位、技能筛选可用方案           |
| 专业教学标准与课程基线     | `GET /open/v1/talent-training-plans/{id}`                               | 教学标准课程模型的领域字段                     |
| 教材知识点与章节           | `GET /open/v1/search` + `GET /open/v1/normalized-refs/{ref_id}/content` | 教材语义切片 + 原文回读                        |
| 检索结果溯源到原文         | `GET /open/v1/raw-objects/{raw_object_id}/download-url`                 | 短期下载 URL，写入报告角标链接                 |
| NEXUS 无证据时的公网补充   | `POST /open/v1/external-search/web-search`                              | 请求级公网搜索（不落库，独立返回）             |

**核心价值：**

- **效率跃升**：报告产出从"人工数月"→"AI 数小时"
- **质量可控**：所有事实均由 Open API 返回真实来源，禁止编造；权限、审计由 NEXUS 侧统一保障
- **可复用底座**：同一套 `/open/v1` 接口可支撑调研报告、专业诊断、课程更新、师资规划等多类 AI Agent 应用，Agent 只需替换 Prompt 与章节模板

## 四、未来展望

NEXUS 不仅解决了当前的信息获取痛点，更构建了企业级知识图谱的坚实底座。未来将持续赋能**智能客服、智能决策辅助、个性化学习路径推荐、人才精准画像**等 AI 应用，成为驱动业务创新、降本增效与持续增长的强大引擎，助力实现更高效的数字化知识管理与价值挖掘。
