# nexus-public-api 全资产类别检索与性能基线

实测日期：2026-11-19（Asia/Shanghai）。主测试窗口为11:33:54—11:34:53；发现、取证恢复、热点复测与故障复核在该窗口前后单独执行。目标服务：`http://10.100.11.51:8000`。凭据由本地既有配置在进程内注入，没有写入报告、参数集或指标。

**当前应优先解决输出体积、证据可用性和语义通道稳定性，再对确定的SQL热点做专项优化。** 大部分已有结构化查询和受限证据读取已达到几十至几百毫秒；仅凭向量表规模无法解释本次发现的问题。特别是，向量metadata持久化瘦身不等于HTTP响应瘦身：一个只有3条命中的教材检索仍返回411,336 bytes。

本轮没有修改业务源码、skill、依赖、配置、部署或数据库业务数据；公开查询按原机制产生审计。没有运行外部联网搜索或自动入库，没有通过内部Console接口绕过公开能力缺口。

使用`.agents/skills/nexus-public-api/SKILL.md`，通过原有`nexus_call.py serve`执行Schema校验、参数编码、认证和连接复用；工具共55个。根据skill路由与实际发现能力选取公开工具。测试驱动仅放在`/tmp`，没有给skill增加新功能。它执行本Agent制定的确定性问题调用计划，并不测量一个未实际运行的自动LLM规划器。

每类5题，覆盖简单查找、条件筛选、内容或详情溯源、数量/分布汇总、综合比较。企业/园区等没有公开聚合工具的类别，明确只对前20条样本统计；岗位和布点使用专用aggregate。语义问题保留默认阈值0.7，不能以零命中快速返回冒充有效答案。

主测试85题各重复3轮，并发1，超时30秒，复用同一个skill连接，不清空数据库或嵌入缓存。先行探针已产生部分预热；因此第一轮也不是真正的冷缓存测试。岗位固定`received_to=2026-11-19T03:33:54.288003Z`，其余数据未锁数据库快照。顺序与查询语料固定，未开展容量或并发压测。

三种时间不能混淆：

1. **HTTP时间**：skill的`elapsed_ms`，从发送请求到完整读取响应，包含服务端、网络和正文传输，不含客户端结果投影。
2. **问题工具链时间**：从开始执行该题到计划终止，含多步调用、序列化及测试驱动记录开销；失败/无命中中断也保留计时，另标完成状态。
3. **完整智能体答复时间**：还应包括意图理解、选工具、上下文处理与答案生成。本轮未对这些步骤自动计时，不能把工具链P95当成最终用户答案P95。

工作区基线为`57cac43`，skill执行器SHA-256与测试集SHA-256保存在summary.json。公开接口没有提供可确认的部署Git SHA，本轮没有远程容器/日志访问，因此不声称远端已经切换到前面构建的镜像，也不把本结果当作pgvector改造的严格前后A/B收益。

## 答复质量与取证效率

90题中，人工基于实际返回数据标记：70题在限定范围内已答、5题补取证后恢复、7题部分可答、1题正文不足、1题语义标签存在缺口、1题筛选组合无匹配、5题公开能力未覆盖。这些是本次语料的证据可用性标记，不是有金标准评测的准确率或召回率；基础事实未独立逐项向官方源核验。

有代表性的实际答复包括：

- 电商岗位17,595条，学历×经验54组；学历缺失303、经验缺失453。重庆采集范围340条、杭州1,601条，大专占比分别63.24%与48.84%。地区是采集范围，不能解释成实际工作地。
- 2026年530701电子商务专业聚合覆盖23省、1,194条布点记录，机构计数合计802；重庆37条/20校。跨年聚合只含2026年，无法回答年度趋势。
- 530701标准课程66条，其中基础16、核心18、拓展32；字面唯一课程名34。文档来源重复与O2O名称变体不能无审计地删除或合并。
- 教材领域目录168本，其中理论167、实训1；“标题含电商且实训”是0，并非平台没有实训教材。

主要证据问题及原因边界：

1. **阈值导致内容题无命中。** 政策题同一范围、同一问题默认0.7三轮均0；阈值0.5/0.0补测能返回5条，最高约0.6657。说明这个范围有可召回候选，不能直接说“未建索引”。但更低分候选是否相关仍要业务金标准评估，不建议全局下调阈值。
2. **目录候选并不等于有内容证据。** 低空产业报告初始仅1条29字标题命中；扩大到全部标题含低空的同类文档，得到8条/4个ref，但内容仍以7—40字短标题为主。继续扩大Top-K并未证明能回答风险与投资分析。补读normalized导读才发现可用的空域、基建和标准问题。
3. **章节首块策略存在局限。** 四类文档的默认首块只含26—48字封面/标题，HTTP均200。相关块补读可恢复专业简介、人才目录和教学案例；法规标准仍只有公布令，属于缺少附件/实质条款，不能由算法凭空补全。
4. **语义标签与精确标签行为不同。** 数据安全案例默认语义标签为0；`tag_type=topic,is_exact_matched=true`三次均4条，164.7/99.1/87.8ms。默认语义模式还会调用嵌入依赖，不能把带tags的目录当成纯SQL查询。本次问题没有显式要求精确匹配，两种路径应明确向Agent解释，不能偷换语义。
5. **有的自然语言条件无法直接由参数精确表达。** 园区`q=重庆`匹配名称或简介，因此返回6个候选并不能保证“名称含重庆”；应改用接口能够表达的问题，或在足够范围分页后本地按名称后过滤。只对第一页过滤后不能声称全量。
6. **数据质量会干扰综合分析。** 岗位清洗标题仍混入薪资/企业/地址；同内容可能有不同raw_jobs.id；方案存在院校名、年限缺失，层次/代码需回源复核，课程名存在拼接。统计要同时呈现样本数、缺失与去重口径，不能用AI补出事实。

## 优化空间一：响应投影与上下文预算

这是本轮证据最明确、与前面metadata瘦身直接衔接的优化方向。

教材命中3条实际HTTP 411,336 bytes；第1条的保留metadata约146,877 bytes，normalized lineage约144,775 bytes，其中包含423个图片URI。图片列表随同一ref的多个chunk重复返回，使网络、JSON解析、skill输出和模型上下文都承受冗余。

已用公开工具实测`search hit → get_available_normalized_ref → get_public_knowledge_chunk`：ref/chunk关系和raw_object_id一致，normalized资产仍有同样423个图片URI，读取39.3ms、chunk21.5ms。后续可使用**新增可选compact响应投影**，保留chunk/ref/version/asset/raw-object锚点、score、相关source_block_ids/locator及有限snippet，完整lineage继续从normalized按需读取。旧完整响应合同保留，不能直接删掉normalized资产内血缘或现有客户端依赖字段。

对已返回3条结果做离线字段投影，包含实际引用锚点和有限snippet的命中列表约4,367 bytes。该数字只是这些字段的离线大小，不含完整响应包络，也不是已上线API的响应或延迟收益。它表明存在两个数量级的字节压缩空间；具体时延收益需在兼容实现后，以相同输入、相同缓存和证据等价测试验证。

skill当前也需要单独分析：`_digest_search_hit`仍递归保留metadata，长图片数组没有按决策用途收敛。新会话教材结果raw约411KB，digest仍约408KB。独立调用设置8,000字符预算后，最终输出仅318 bytes，`applied_mode=minimal`，丢失全部chunk/ref候选。输出超限如果只留下trace，会阻断skill推荐的后续批量取证。

模式只在HTTP完成后本地处理，不能从该表声称服务端SQL或网络下载加速；不同请求的少数字节差主要为trace等包络。课程、方案专用投影应把“课程名单/统计”与“课程内容/原文证据”分开。培养方案详情约527,059 bytes，其中training_specification、career_orientation和courses是主要内容；只问年限/课程数量时可直接复用列表事实，避免不必要get。

## 优化空间二：工具选择、取证与调用计划

优先可在调用方式/skill说明中改进，但本轮没有修改它们：

- 明确“精确业务标签”与“语义相似标签”，已知枚举标签优先显式指定type与exact；自由表达仍保留语义能力及失败说明。不能直接把所有语义标签改成精确匹配。
- 目录结果只证明存在候选。读取前根据section预览选择问题相关块，命中只有封面/目录时触发一次有限回退；相关证据已足够时避免读完整文档。法规附件未入库应直说缺口。
- 综合比较要求覆盖多个来源：记录候选ref数、实际有内容的ref数和引用来源数。不能把top_k=8的8条同源chunk误认为8份材料。
- 数量/分布优先SQL聚合。只有部分领域有专用聚合，不支持时限定样本；同问题中的列表字段足够作答就不再get详情。依赖步骤保持顺序，无依赖的独立查询可在未来用有限并发或批量API减少等待，但本轮未验证并发收益。
- 可复用同一turn已成功的相同目录/证据调用，但不要把某用户/权限范围结果做无边界跨请求缓存。已有Console内部去重与独立skill执行器并非同一运行时，不能假设两者已共享去重。
- 修正资源发现编码与skill路由别名的一致性：实际返回major_distribution、occupational_ability_analysis、occupation_dictionary、standard_course，静态route映射主要使用major_offering、ability_analysis、occupation、teaching_standard_course；teaching_standard和talent_training_plan的静态resource-type路由偏文档，skill正文又要求领域工具优先。Agent本轮手工按发现能力消解，后续应减少这类选择成本。

## 优化空间三：服务端热点与故障隔离

以下为当前源码静态分析结合黑盒表现的候选，未取得实际SQL执行计划，不能当作已经确认的瓶颈根因：

- 市场岗位、企业与园区列表`page_rows`先完整count再分页；岗位列表带provenance关联、文本子串条件和采集时间排序。下一步对慢trace对应SQL执行受限`EXPLAIN (ANALYZE, BUFFERS)`，核对计数、join、过滤、排序各自耗时；再决定索引、覆盖查询或可选不精确计数。不要为了快而直接取消现有total语义。
- 岗位聚合在分页分组计数之外另读sample_count和各分组字段missing_counts。可评估共享窄列过滤子查询、一次条件聚合计算缺失值，减少重复扫描；必须验证同样的received_to、raw_jobs.id去重口径、NULL/空字符串及分组统计。
- 企业经营范围/名称为字面子串匹配，普通B-tree通常不能解决任意`%关键词%`；需根据实际选择率、排序和已有索引评估pg_trgm，不能无证据先建多组索引。
- 标签503的代码路径明确与语义标签嵌入调用失败有关；当前不指定tag_type会跨多个受控类型处理。可评估同查询向量复用、按明确type收敛、依赖超时与错误分类。500及断链必须先查服务端堆栈；后续重连/重试只对明确只读请求采取有限次数与退避，不掩盖原始失败率。
- 检索阶段需要区分scope目录SQL、collection选择、query embedding、向量召回、normalized血缘hydrate、公开准入/权限、序列化与审计提交。复测时不要将本地digest耗时混入数据库检索时间。只需在已有trace/结构化日志中补充分段证据，不需要新增产品化监控中心或Redis依赖。

已有collection路由与metadata瘦身主要作用于向量检索及数据库I/O；岗位、园区、企业、布点等按领域表走SQL，不会直接因该改造获得同等倍数提升。API重新hydration后的lineage响应体仍然很大，是单独的消费边界问题。本轮未改代码，也未证明当前远端部署SHA，不能把这些现象直接认定为57cac43新引入或已解决。
